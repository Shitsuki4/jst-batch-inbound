# 收货小助手（聚水潭扫码入库）

面向仓库收货台的 Windows 桌面工具：扫物流单号、扫商品条码，自动对照聚水潭采购单统计实收，
一键生成入库单；同时按物流单号自动录制开箱视频，方便售后举证。

当前版本：**4.1.1**　·　[下载最新版](https://github.com/Shitsuki4/jst-batch-inbound/releases)

## 功能

- **扫码收货**：扫物流单号开批次，扫商品条码累加实收（同一商品扫几次记几件），数量只允许正整数。
- **采购单对单**：自动关联聚水潭采购单，实时显示应收、实收、差异；同一 SKU 在采购单多行出现时按 SKU 合并计算。
- **入库**：按实收生成聚水潭入库单，提交前留快照、按指纹防重复，网络超时不会自动重建，最后回读核对数量。
- **无采购单收货 / 多采购单联合收货**：登记无单到货、多张采购单合并收货与汇总对单。
- **快递单登记**：流程与无采购单收货相同（先扫物流单号再扫商品），但完全不绑定采购单；左栏显示当前物流单号收货明细；导出 CSV 每个物流单号一行：单号 | 扫描时间 | 明细（明细与「复制明细文字」相同，同一单元格多行）。数据单独存于 express.db。
- **无采购单收货导出**：物流单明细增加「扫描登记时间」列（物流单号扫描时间，格式 2026/10/17 20:46:53）。
- **PDA 联动**：安卓 PDA 通过局域网配对后扫码，配对码有按 IP 限流和输错作废保护。
- **自动录像**：确认物流单号即开始录制，切换单号自动分段；可设单段时长（分钟）/ 大小（GB，可填 0.5）上限（填 0 不限制），到上限自动收尾并为同一单号续录新段；修改正在录像的物流单号时会询问是否按新单号重新录制；监控浮窗可移动、缩放、置顶。
- **导出**：差异报告、扫码流水 CSV，支持按时间、采购单、物流单号、商品编码筛选。

## 安装

在 [Releases](https://github.com/Shitsuki4/jst-batch-inbound/releases) 下载：

| 文件 | 适用 |
| --- | --- |
| `ReceivingAssistant-<版本>-Offline-Setup.exe`（约 500 MiB） | 推荐。自带 .NET、Python 后端、FFmpeg、WebView2，内网或断网电脑也能装 |
| `jst-batch-inbound-desktop-<版本>-win-x64.zip`（约 86 MiB） | 便携版，缺依赖时首次启动会通过 `winget` 安装 |
| `ReceivingAssistant-Deps-<版本>-Setup.exe`（运行依赖安装程序） | 与便携版配套：先运行它安装 FFmpeg/ffprobe 和 WebView2 固定运行时，便携版即可在断网电脑使用，无需 `winget`。便携 ZIP + 依赖 exe = 离线完整安装包之外的另一种离线方案 |

- 按当前用户安装，不需要管理员权限。
- 运行依赖安装程序把组件装到 `%LOCALAPPDATA%\ReceivingAssistant\runtime`，在“应用和功能”里显示为“收货小助手运行依赖”，可单独卸载，不碰业务数据。
- 业务数据、设置、登录资料在 `%LOCALAPPDATA%\ReceivingAssistant\v3`，升级时保留；卸载时默认保留，也可以选择删除部分或全部数据。
- 开始菜单有“卸载收货小助手”。卸载时可选：保留全部数据（默认）/ 自定义保留（收货数据库、录像、导出文件、设置与登录记忆、缓存日志）/ 完全卸载；小助手仍在运行时可选择强制结束后继续。静默卸载支持 `/FORCECLOSE`、`/PURGEDATA`，详见 [`desktop/README.md`](desktop/README.md#卸载)。
- **升级前请先正常退出小助手**；业务服务还在运行时安装程序会拒绝继续，以免装出新旧混合的文件。
- 安装包暂未做代码签名，Windows 可能提示“未知发布者”。

首次使用：进入录像设置选择摄像头和录像目录，并**显式保存磁盘预警 / 停止阈值**，未配置阈值时不会开始录像。

## 架构

```
desktop/
├── src/                 WPF 宿主 Receiving.Native.exe（.NET 10）
│                        监控浮窗、FFmpeg 录像、录像索引、WebView2 工作区
├── backend/app/         Python 本地服务 Receiving.Service.exe
│                        聚水潭接口、SQLite、PDA、导出、网页界面（web/）
├── installer/           Inno Setup 离线安装包脚本与说明文档
├── tests/               录像器回归测试
└── build-*.ps1          构建脚本
```

宿主启动时为后端分配端口和令牌；后端只监听 `127.0.0.1`，并校验 Host / Origin。
后端端口被占用时以退出码 75 退出，宿主换端口重启（最多 5 次）。

## 开发

需要 Windows、.NET 10 SDK、Python 3.11、WebView2、FFmpeg/ffprobe。

```powershell
# 运行宿主
dotnet run --project desktop/src/Receiving.Native.csproj

# 构建便携包（含 Python 回归与录像回归）
powershell -ExecutionPolicy Bypass -File desktop/build-windows.ps1

# 只构建不跑测试
powershell -ExecutionPolicy Bypass -File desktop/build-windows.ps1 -SkipTests
```

后端测试（Linux / macOS 也能跑大部分）：

```bash
cd desktop/backend/app
pip install cryptography qrcode Pillow
python regression_runner.py        # 回归套件
python concurrency_fixes_test.py   # 单个测试文件直接运行
```

离线安装包构建、安装级验收等完整说明见 [`desktop/README.md`](desktop/README.md)。

## 发布

1. 修改 `desktop/src/Receiving.Native.csproj` 里的 `<Version>`（标签版本必须与之一致，否则 CI 直接失败）。
   同时修改 `desktop/backend/app/app_version.py` 的 `VERSION`（Python 后端唯一版本来源，备份清单和原生健康检查都用它；回归测试会校验它与 csproj、`offline_setup.iss` 一致）。
2. 合并到 `main` 后打标签：

```powershell
git tag desktop-vX.Y.Z
git push origin desktop-vX.Y.Z
```

CI（[`build-desktop-exe.yml`](.github/workflows/build-desktop-exe.yml)）会构建便携 ZIP、离线安装包和运行依赖安装程序，
跑完回归与安装 / 覆盖升级 / 卸载验收后创建 GitHub Release。PR 修改 `desktop/**` 时也会自动构建。

已安装 4.0.x 的电脑可通过「设置 → 软件更新」自动更新到本版本（也可手动下载安装包覆盖安装）。

#### 全局锁重构（#20）

- 全局锁重构：调用聚水潭接口（查单、明细、货主、缺码查询、登录恢复）、生成/续作入库、盘点、无采购单/联合收货核对、导出文件和备份复制都移到全局锁外。接口变慢时，其他会话扫码、PDA、页面刷新不再被卡住。

### 4.0.0

#### 自动更新

- 自动检查更新：「设置 → 软件更新」可选下载渠道（GitHub 原链接 / 加速站 gh-proxy.com），默认每天自动检查一次；发现新版本时顶部横幅提示（每个版本可关闭一次）。下载后按 `SHA256SUMS.txt` 校验，原生端安装前再复核；正在录像或入库中时拒绝安装。安装版运行新安装程序覆盖升级，便携版解压到新文件夹（旧文件夹数据不自动迁移）。

#### 备份恢复

- 备份恢复：设置 →「安全备份」卡片内可列出备份（手动 / 每日自动 / 升级前自动 / 恢复前自动备份）、预览行数对比，并以红色警告列出恢复后会丢失的入库单号（有重复入库风险）；也可从备份文件夹或压缩包恢复。需输入「恢复」确认；恢复前自动再备份一次，替换在重启时进行，任何一步失败自动回滚。正在录像、有未完成入库 / 盘点 / PDA请求或PDA服务运行时拒绝恢复。桌面版恢复后自动安全退出并重新打开。
- 自动备份的版本标签改为与应用版本同源（`app_version.py`），此后每次升级首次启动都会先做一次「升级前」备份（此前一直停在 2.0.21，3.0.x 升级不会触发）。
- 未知条码学习数据 `learned_codes.db` 与其他数据库一样纳入备份与恢复（列表、预览、暂存、启动时替换、失败回滚）；恢复不含该库的旧备份时保留当前学习数据。

#### 未知条码学习

- 未知条码学习：商品资料查不到的条码可在有采购单 / 无采购单 / 联合收货 / PDA 收货时人工学习到某个商品，之后同码按该商品识别并在明细标「学习匹配」。商品资料始终优先，学习仅兜底；按公司 + 货主 + 仓储共享；设置 →「商品资料」可查看、搜索、删除、导出 CSV。

#### 操作记录

- 新增「操作记录」页：电脑和 PDA 的扫码加数、改数量、删除明细、物流单号增改删、挂起 / 结单 / 删除、入库请求与结果（失败也记）、登录 / 切换账号、设置修改等都会留下审计记录，含操作前后数量和来源设备；可按时间、设备、操作类型、采购单、SKU 筛选，服务端分页，支持 CSV 导出；收货明细弹窗可「查看此单操作记录」。默认保留 180 天（可设 7–3650 天），独立保存在 `operation_log.db` 并纳入备份（恢复备份时保留当前操作记录，不会被备份覆盖）；不记录密码、Cookie、验证码或令牌，记录写入失败不影响业务操作。

#### 物流单号提示

- 普通（有采购单）收货扫描 / 输入新物流单号时，会只读检查「无采购单收货」中是否已登记同一单号（忽略首尾及中间空白、不区分大小写，完全一致才算）。命中**未绑定采购单且未提交入库**的登记时，先弹出确认框（登记时间、件数 / SKU数、当前状态），**此时尚未建立物流子批次**：选「去无采购单绑定」直接打开该登记，不会留下空子批次；选「仍在此处收货」则照常建立，本页面会话内同一单号不再重复提示。若该登记已绑定**本采购单**，同样提示“请勿重复收货”；绑定其他采购单或已提交入库的登记不提示。已在本单建过的物流单号补扫不再检查。
- PDA 与原生 / 旧调用方不走确认流程：物流子批次照常一次建立，响应中附带 `unplanned_hint` 提示字段（PDA 页面会在“物流单号已确认”后显示该提示）。
- 检查使用独立只读连接读取 `unplanned.db`，不初始化无采购单模块、不写库；库不存在时跳过，读取出错只记日志，绝不阻断收货。

#### 审查 P1 修复

- PDA 不再驱动电脑端录像：PDA 扫物流单号 / 扫商品不会让电脑端开始、切换录像或更新录像旁注；PDA 扫挂起单的物流单号时只建物流子批次，不再把它设为「当前收货」，电脑端正在收的单子不会被挂起。电脑端扫码行为不变。
- PDA 收货单列表（每 2 秒轮询）每次只取一次货主 / 分仓范围，成功和失败都缓存 60 秒（登录、切换账号、停用 PDA 时立即失效）；需要访问聚水潭时在全局锁外进行，不再卡住电脑端扫码。清单读取失败时列表仍显示（标注「范围待核实」并给出提示），但扫码、改数、入库等写操作会被拒绝并说明原因。
- 「应收」口径统一为本轮应收（本轮开始时的采购数量 − 聚水潭已入库，与电脑端「本轮」一致）：差异表、左栏采购明细、结单 / 暂存返回的差异、远程管理页对单都按它计算差异，并另列「采购总数」供对照。旧记录或缺少可靠起始数量的商品仍按采购总数对照，并标明「本轮应收待核实」。
- 删除整张普通收货单时，若该单正在录像（是当前收货单，或最近一次录像关联指向它），会通知电脑端停止录像；删除无关的历史单不打断当前录像。
- 删除接口更严格：删除整单必须指定收货单（不再缺省删除「当前收货中」的单）；删除物流子批次会校验它属于指定的收货单（未指定时为当前收货单）。已结单的轮次仍可修改数量、删除子批次、生成入库，行为不变。
- 卸载：「本机设置与登录记忆」类别包含远程管理页数据 `data\remote-access`（开关、管理员密码哈希、TLS 证书与私钥），「缓存与日志」包含录像库内置播放器页面 `library-player`；无论保留哪些数据，卸载时都会删除远程管理页添加的 Windows 防火墙放行规则（需要管理员权限，交互卸载会请求一次授权）。
- 远程管理页历史筛选的日期范围改为「范围内有活动」：开单时间或任一物流单的首次扫描时间落在所选日期内才显示，不再出现范围内毫无活动的单子。

#### 并发死锁修复

- 本机服务 / PDA 接口的响应改为在请求处理（含操作记录写入、回滚）全部结束、释放全局锁之后才发出：收到回复即代表该请求已不再使用共享数据库连接。修复 4.0 集成 CI 偶发卡死（操作记录钩子在回复后仍读收货库，与调用方同时使用同一 SQLite 连接导致死锁）。
- 回归测试超时时打印的线程栈不再因 Windows CI 控制台 cp1252 编码报错而丢失（输出改为 UTF-8，无法编码的字符替换）。

### 3.0.3

- 无采购单收货新增「复制明细文字」按钮。
- 开始菜单新增“卸载收货小助手”。
- 卸载时可选择数据处理方式：保留全部数据（默认，与以前一致）、自定义保留哪些类别（收货数据库与备份、录像、导出文件、本机设置与登录记忆、缓存与日志，显示实际占用空间），或完全卸载（二次确认后删除全部数据，不可恢复）。独立的运行依赖目录不受影响。
- 小助手仍在运行时，卸载程序不再只是拒绝：会列出正在运行的进程，可选择“强制结束并继续卸载”（只结束安装目录内的进程，并提示可能中断 ERP 提交和录像）或“取消”。
- 静默卸载：默认保留全部数据、运行中拒绝卸载；新增 `/FORCECLOSE`（强制结束后继续）和 `/PURGEDATA`（删除全部数据）开关。安装 / 覆盖升级时检测到小助手在运行仍然拒绝继续，行为不变。
- “应用和功能”中的名称改为“收货小助手”。
- CI 安装验收新增：开始菜单卸载快捷方式、运行中卸载被拒绝 / `/FORCECLOSE` 成功、默认保留数据、卸载后重装、`/PURGEDATA` 删除数据但不碰运行依赖目录。
- 新增「远程管理页（IPv6）」：默认关闭，在「设置 → 远程管理页」启用后，手机 / 电脑浏览器可通过本机公网 IPv6 直连 `https://[地址]:端口/`，**只读**查看收货历史（采购单 / 无采购单 / 联合收货及明细）和录像（搜索、浏览器内在线播放，可选允许下载）。独立 HTTPS 监听（自签名证书，设置页显示 SHA-256 指纹）、管理员账号密码（scrypt 加盐哈希）、会话超时、登录限速与锁定、审计日志；远程端无法访问任何收货 / 入库 / 删除 / 设置 / 剪贴板 / PDA 接口。详见 [desktop/README.md](desktop/README.md#远程管理页ipv6)。
- **录像查询界面重构**：顶部一个搜索框（可直接扫码，物流 / 采购 / 外部单号 / 商品编码 / 备注），日期快捷（今天 / 近7天 / 近30天 / 全部 / 自定义）与状态筛选（已完成 / 在录 / 异常 / 售后保护 / 已归档），默认显示今天的录像。
- 列表支持 Ctrl / Shift 多选和复选框列（表头复选框全选当前列表），各列可排序，状态着色；数千条录像后台读取、虚拟化显示，不卡界面。
- 内置播放器（WebView2）：播放 / 暂停、拖动定位、0.5 / 1 / 2 倍速、全屏；下方列出该录像的扫码记录，点击跳到对应时间；截图（PNG）、导出片段（FFmpeg 不重新编码）、打开所在文件夹、用系统播放器打开。
- 删除所选：确认框列出数量、大小和跳过项；在录片段始终跳过，售后保护片段需勾选“同时删除售后保护片段”才会删除；视频已缺失的条目可直接清理索引，并同步清理不再被引用的采购关联。售后保护 / 解除支持批量；清理旧录像改为“选出 90 / 180 天以上候选 → 删除所选”，不再有单独的删除入口。
- 修复旧界面无法全选、无法删除：旧表格只允许单选、勾选框没有全选且与选中状态脱节，删除又只在“清理候选”模式下、且只允许超龄片段。
- CI 新增录像查询界面独立验收（`Receiving.Native.exe --library-ui-test`）。

### 3.0.2

- 修复离线完整安装程序未给 WebView2 固定运行时目录授予 AppContainer 读取/执行权限的问题：Windows 10 上业务界面可能启动即闪退。安装与覆盖升级后都会自动重新授权，验收脚本也会检查该 ACL。
- 新增运行依赖安装程序（`ReceivingAssistant-Deps-<版本>-Setup.exe`，本地构建名“收货小助手-<版本>-运行依赖安装程序”）：与便携 ZIP 配套，离线安装 FFmpeg/ffprobe 和 WebView2 固定运行时到 `%LOCALAPPDATA%\ReceivingAssistant\runtime`，断网电脑不再需要 `winget`。
- 便携版查找依赖时，在程序旁 `runtime\` 之后、系统安装之前，优先使用运行依赖安装程序装好的共享组件；离线完整安装版行为不变。
- 环境检查窗口提示：断网电脑可先运行「运行依赖安装程序」。
- CI 构建并验收运行依赖安装程序（静默安装、`ffmpeg -version` / `ffprobe -version`、便携版依赖检查、静默卸载），随 Release 一起发布。
