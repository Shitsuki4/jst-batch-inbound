# 收货小助手（聚水潭扫码入库）

面向仓库收货台的 Windows 桌面工具：扫物流单号、扫商品条码，自动对照聚水潭采购单统计实收，
一键生成入库单；同时按物流单号自动录制开箱视频，方便售后举证。

当前版本：**4.1.8**　·　[下载最新版](https://github.com/Shitsuki4/jst-batch-inbound/releases)

## 功能

- **多模式扫码收货**：
  - **采购单收货**：扫物流单开批次、扫商品条码累加实收；自动关联聚水潭采购单，实时显示应收、实收与对单差异，同一 SKU 在采购单多行出现时自动合并计算，数量只允许正整数。可「更换采购单」：改采购单号或外部单号后按新采购单重新匹配已收商品，先预览、确认后才更换，本轮已生成入库单时不能更换。
  - **无采购单收货 / 多采购单联合收货**：支持到货无单登记，以及多张采购单合并收货与汇总对单。
  - **快递单登记**：不绑定采购单的独立登记流；左栏实时显示当前物流单收货明细；导出 Excel（.xlsx）每个物流单号一行：单号 | 扫描时间 | 明细（明细单元格内换行）。数据单独存于 express.db。
- **入库与防重机制**：按实收一键生成聚水潭入库单，提交前留快照、按指纹防重复，网络超时不会自动重建，最后回读核对数量。
- **全自动录像举证**：确认物流单号即开始录制，切换单号自动分段；可设单段时长（分钟）与大小（GB，可设 0.5）上限（0 为不限制），到上限自动收尾并为同一单号续录新段；修改正在录像的物流单号时询问是否按新单号重新录制；监控浮窗可移动、缩放、置顶。
- **录像查询与回放**：内置高清播放器，支持按物流单号、采购单、外部单号、商品编码及备注检索，支持多倍速播放与秒级定位扫码节点；提供售后保护标记与旧录像批量清理。
- **跨来源全局检索**：在记录查询、录像查询、远程管理页均可一次性检索 4 种来源（普通/无采购单/联合/快递单）的登记记录，支持不分大小写与模糊匹配，并能精准列出「有登记但无录像」的单号。
- **远程管理页（cpolar 穿透 / IPv6）**：手机或外部电脑用浏览器打开，什么都不用装，只读查验收货历史、入库单据与录像，权限严格隔离。
- **PDA 局域网联动**：安卓 PDA 通过局域网配对后扫码作业，配对码提供按 IP 限流和输错作废保护。
- **未知条码学习与操作审计**：新条码人工绑定后自动记住并全端共享；所有扫码改数、入库与系统操作完整留痕于独立审计日志；支持一键安全备份与恢复。
- **错误码与诊断日志**：每条报错都带「类别-四位数字」的错误码和日志编号（见 [docs/错误码.md](docs/错误码.md)），只有聚水潭明确拒绝权限才提示 E-JST-1401；报错记入数据目录 `data\logs` 的诊断日志（满 2 MB 轮换，不含密码、令牌、Cookie），在「设置 → 诊断与日志」导出诊断包或打开日志文件夹。
- **报表导出**：差异报告、商品明细、扫码流水，支持按时间、采购单、物流单号、商品编码筛选导出。所有导出文件（历史导出、收货明细、诊断包、联合收货、操作记录等）都放进导出目录，目录结构为 `根目录\日期\类别\文件`；在「设置 → 数据与备份 → 导出保存目录」可改成自己的文件夹（和录像目录一样设置），默认在安装目录的 `backend\导出`。

## 安装

在 [Releases](https://github.com/Shitsuki4/jst-batch-inbound/releases) 下载：

| 文件 | 适用 |
| --- | --- |
| `ReceivingAssistant-<版本>-Offline-Setup.exe`（约 500 MiB） | 推荐。自带 .NET、Python 后端、FFmpeg、WebView2，内网或断网电脑也能装 |
| `jst-batch-inbound-desktop-<版本>-win-x64.zip`（约 86 MiB） | 便携版，缺依赖时首次启动会通过 `winget` 安装 |
| `ReceivingAssistant-Deps-<版本>-Setup.exe`（运行依赖安装程序） | 与便携版配套：先运行它安装 FFmpeg/ffprobe 和 WebView2 固定运行时，便携版即可在断网电脑使用，无需 `winget`。便携 ZIP + 依赖 exe = 离线完整安装包之外的另一种离线方案 |
| `ReceivingAssistant-<版本>-Upgrade-Setup.exe`（升级安装程序，约 75 MiB） | 给已经装过离线完整安装程序或运行依赖安装程序的电脑升级用。内容和便携 ZIP 一样，不带 FFmpeg 和 WebView2，用电脑上已经装好的那一份；运行组件缺失或版本不一致时拒绝安装，请改用离线完整安装程序 |

- 按当前用户安装，不需要管理员权限。
- 升级安装程序：
  - 装过离线完整版的电脑：原地升级到同一个安装目录，`runtime\` 和 `%LOCALAPPDATA%\ReceivingAssistant\v3` 里的数据都不动。
  - 只装过运行依赖、一直用便携版的电脑：装成安装版，用运行依赖安装程序的共享组件。安装版数据和便携版文件夹是分开的；安装时可以在“便携版数据”页选中便携版文件夹，把它的业务数据和设置**复制**到安装版（只复制不移动，便携版文件夹不改；录像不复制，继续存在原来的位置；安装版已有数据时不导入）。静默安装用 `/PORTABLEDATA="便携版文件夹"`。
  - 两种组件都没有，或者版本和这一版固定的不一样：安装程序直接拒绝，提示改用离线完整安装程序，不做任何改动。
  - 安装版「设置 → 软件更新」会自动挑选：本机组件和新版本固定的完全一致就下载升级安装程序，否则下载离线完整安装程序。
- 运行依赖安装程序把组件装到 `%LOCALAPPDATA%\ReceivingAssistant\runtime`，在“应用和功能”里显示为“收货小助手运行依赖”，可单独卸载，不碰业务数据。
- 业务数据、设置、登录资料在 `%LOCALAPPDATA%\ReceivingAssistant\v3`，升级时保留；卸载时默认保留，也可以选择删除部分或全部数据。
- 开始菜单有“卸载收货小助手”。卸载时可选：保留全部数据（默认）/ 自定义保留（收货数据库、录像、导出文件、设置与登录记忆、缓存日志）/ 完全卸载；小助手仍在运行时可选择强制结束后继续。静默卸载支持 `/FORCECLOSE`、`/PURGEDATA`，详见 [`desktop/README.md`](desktop/README.md#卸载)。
- **升级前请先正常退出小助手**；业务服务还在运行时安装程序会拒绝继续，以免装出新旧混合的文件。
- 安装包暂未做代码签名，Windows 可能提示“未知发布者”。

首次使用：进入录像设置选择摄像头和录像目录，并**显式保存磁盘预警 / 停止阈值**，未配置阈值时不会开始录像。

## 架构

```
desktop/
├── src/                 WPF 宿主 Receiving.Native.exe（.NET 10）
│                        监控浮窗、FFmpeg 录像、录像索引、WebView2 工作区
├── backend/app/         Python 本地服务 Receiving.Service.exe
│                        聚水潭接口、SQLite、PDA、导出、网页界面（web/）
├── installer/           Inno Setup 离线安装包脚本与说明文档
├── tests/               录像器回归测试
└── build-*.ps1          构建脚本
```

宿主启动时为后端分配端口和令牌；后端只监听 `127.0.0.1`，并校验 Host / Origin。
后端端口被占用时以退出码 75 退出，宿主换端口重启（最多 5 次）。

## 开发

需要 Windows、.NET 10 SDK、Python 3.11、WebView2、FFmpeg/ffprobe。

```powershell
# 运行宿主
dotnet run --project desktop/src/Receiving.Native.csproj

# 构建便携包（含 Python 回归与录像回归）
powershell -ExecutionPolicy Bypass -File desktop/build-windows.ps1

# 只构建不跑测试
powershell -ExecutionPolicy Bypass -File desktop/build-windows.ps1 -SkipTests
```

后端测试（Linux / macOS 也能跑大部分）：

```bash
cd desktop/backend/app
pip install cryptography qrcode Pillow
python regression_runner.py        # 回归套件
python concurrency_fixes_test.py   # 单个测试文件直接运行
```

离线安装包构建、安装级验收等完整说明见 [`desktop/README.md`](desktop/README.md)。

## 发布

1. 修改 `desktop/src/Receiving.Native.csproj` 里的 `<Version>`（标签版本必须与之一致，否则 CI 直接失败）。
   同时修改 `desktop/backend/app/app_version.py` 的 `VERSION`（Python 后端唯一版本来源，备份清单和原生健康检查都用它；回归测试会校验它与 csproj、`offline_setup.iss` 一致）。
2. 合并到 `main` 后打标签：

```powershell
git tag desktop-vX.Y.Z
git push origin desktop-vX.Y.Z
```

CI（[`build-desktop-exe.yml`](.github/workflows/build-desktop-exe.yml)）会构建便携 ZIP、离线安装包、运行依赖安装程序和升级安装程序，
跑完回归与安装 / 覆盖升级 / 卸载验收后创建 GitHub Release。PR 修改 `desktop/**` 时也会自动构建。

## 版本记录

### 4.1.10

- **「有采购单收货」商品名称不再叠两遍、不再挤成一条**：商品名称和规格（款式名 / 简称）内容重复时只显示一次（规格已包含在名称里就不显示，规格不同才作为副标题），左侧采购单明细、右侧当前物流单号、对单汇总、配对表、差异单和无采购单收货 / 快递单登记的明细都用同一套规则。
- **当前物流单号表格**：改成「商品 | 数量 | 操作」三列，编码和单位条码放进商品单元格的灰字行，「编辑资料」跟着商品走；数量和操作列按内容收紧，商品列至少 200px，长名称最多两行、超出省略、悬停看全名。以前窗口一窄，商品列会被挤到只剩几个字宽、逐字换行并被裁掉，表格还会出现横向滚动条。
- **当前物流单号只显示本单号扫到的商品**：「以下商品已在其他物流单号收满，无需再扫」那一段去掉了，各商品一共收了多少看左侧采购单明细。

### 4.1.9

- **远程管理页支持 cpolar 穿透**：「设置 → 远程管理页」新增「cpolar 穿透」，开启后多一个只绑 `127.0.0.1:18480`（可改）的明文 HTTP 入口，给收货电脑上的 cpolar 免费版映射成公网 https 地址。访问的人什么都不用装，收货电脑不需要公网 IPv6、不用改防火墙。设置页列出要填进 cpolar 的本地地址和创建隧道的步骤；「IPv6 直连」可以单独关掉。本机收货服务端口不能用作入口。步骤见 [desktop/README.md](desktop/README.md#cpolar-穿透免费版)。
- **经 cpolar 访问时的登录保护**：经过 cpolar 的请求来源都是 `127.0.0.1`。以前按来源计数时，一个人输错 5 次会把所有人锁 15 分钟，而任何一个人登录成功后，整个入口又会被当成「登录成功过的网络」、绕过全局暂停。现在登录成功过的浏览器凭设备 Cookie（30 天）单独计数、不受全局暂停影响；没登录成功过的浏览器共用一个限速桶（10 次失败暂停 5 分钟）；来源地址不再记为「登录成功过的网络」。改管理员用户名 / 密码后设备记录清空。
- 远程管理页用 `http://` 打开时自动跳到 https。

### 4.1.8

- **扫码枪连扫不再打进数量框**：有待确认数量时，下一件的条码打进数量框会被认出来：数量框恢复成原来的数，按这个数确认上一件，再把这串条码当作下一次扫码。
- 扫码入账后接口带回本轮数量，商品列表即时刷新。
- **分批到货**：
  - 物流单号写进聚水潭入库单备注（保留原备注）；开单前到聚水潭核对同一采购单下仍有效的入库单，备注里已有同一物流单号（另一台电脑开的）就不再开单（E-INB-2010）。备注没写成只提示（E-INB-2011），不影响已生成的入库单。
  - 新开一轮时读取聚水潭里还没确认的入库草稿，从本轮应收里扣掉，页面上说明扣了多少；读不到时提示应收可能偏多。
  - 换收货方式不再一律被拦：只有别处还有没处理完的入库记录（E-INB-2012），或同一物流单号已在别处入过库，才会拦下。
  - 同一物流单号大小写不同算同一批；按物流单号导出时 `%`、`_` 按字面匹配。
- **恢复备份**：有采购单、无采购单、联合收货三个库都核对，按收货方式分开列出恢复后会丢的入库单；某个库读不出来时单独提醒。
- **导出目录**：「设置 → 数据与备份 → 导出保存目录」可自定义，和录像目录一样设置，目录结构为 `根目录\日期\类别\文件`。历史导出、收货明细、诊断包、联合收货和操作记录等导出文件都放进这里；改目录后旧文件留在原处，界面会提示。卸载时，装在安装 / 数据目录里的导出目录按「导出文件」分类处理，自选的外部目录不会被删除。
- **CSV**：纯数字长单号按文字写，Excel 打开不再变成科学计数；所有 CSV 都防公式注入；收货明细默认导出 Excel。
- **最近的报错**：默认列出 WARN 和 ERROR；按错误码或日志编号查时不限级别；桌面程序的旧日志也一并读入，按实际时间排序。
- **对单界面统一**：无采购单匹配（后补采购单核对预览）、暂存对单、结单对单和联合收货汇总，都改用「有采购单收货」同一套进度卡（已齐 / 短收 / 超收 / 未收）和商品表（商品信息 | 应收 | 实收 | 差额），由公共组件 `receiving-summary.js` 生成；功能和流程不变，相似商品配对视图保留在折叠区里。
- **无采购单收货左侧汇总区修复**：匹配采购单、全部入库后，汇总区不再出现只有表头的空配对表和撑出卡片的宽表；商品表用固定列宽（不再套用旧汇总表的「首列占满、单行省略」），数量列不再被挤窄、行高不再被撑开；相似商品配对表在折叠区内自适应宽度；还有短收时进度不再四舍五入显示成 100%；无采购单的商品行不再悬停显示「采购 待核实 / 入库 待核实」。
- **设置页**：去掉视频设置里多出的“}”，「选择目录」「枚举设备」按钮和输入框对齐，重写录像目录说明文字。
- **安全**：本机接口要求令牌（E-REQ-1401），网页通过桌面程序写入的 HttpOnly Cookie 访问；远程管理页 30 天内登录成功过的网络不再被全局锁定拦住；自动更新的校验值必须来自 GitHub 原地址（连不上 GitHub 的电脑需要手动下载安装）。
- 入库数量不再经过浮点数，小数位过多时直接停止，不会悄悄舍入。
- CI 跑全部 JavaScript 测试，并补上之前只在本地跑的 Python 测试。

### 4.1.7

- **报错都带错误码**：格式统一为「类别-四位数字」，报错文字前面带上错误码和日志编号，例如 `[E-NET-2001] 连不上聚水潭服务器`、`[E-PO-1001] 未找到该采购单`、`[E-JST-1401] 当前聚水潭账号无此操作权限`。全部错误码、含义和处理办法见 [docs/错误码.md](docs/错误码.md)。
- **不再一律提示“无权限”**：断网、超时、登录失效、聚水潭业务校验、采购单不对、程序出错各自显示真实原因和错误码；只有聚水潭明确拒绝权限时才提示 E-JST-1401。
- **分批到货**：物流单号会写进聚水潭入库单备注；开单前核对同一采购单下有没有别的电脑已为同一物流单号开过、仍有效的入库单，有就拦下（E-INB-2010）。新开一轮时，聚水潭里还没确认的入库草稿从本轮应收里扣掉。
- **诊断日志**：每条报错都记入数据目录 `data\logs` 下的 `diagnostic.jsonl`（本机服务、PDA、远程管理页）和 `native-diagnostic.jsonl`（桌面程序），满 2 MB 换新文件、最多保留 5 个旧文件，不记录密码、令牌、Cookie。「设置 → 诊断与日志」可以导出诊断包、打开日志文件夹、按错误码或日志编号查最近的报错。
- **更换采购单并重新匹配**：有采购单收货页新增「更换采购单」，输入新的采购单号或外部单号，先预览已收商品在新采购单上的匹配、不在新单上的和超收的，确认后才更换。物流单号、实收数量、扫码记录和录像都留在原批次上；本轮已生成过入库单时不能更换（E-PO-2002），预览后数据有变化要重新预览（E-PO-2005）；每次更换都记入操作记录。
- 安装程序和自动更新的报错也带上了错误码（E-INS、E-UPD）。

### 4.1.6

- 修复有采购单收货中，自动录像未就绪时被误报为“连接中断 / 没连上本机收货服务”的问题。现在显示实际的录像拦截原因，真实的网络错误仍使用连接中断提示。
- 新增“重新确认当前物流单”入口：重启助手或恢复旧批次后，可重新建立当前物流单的录像关联，等待顶部显示正在录制后继续收货。
- 确认数量被录像校验拦截时，保留待确认商品、数量和操作编号，并暂停处理下一次扫码；不会增加实收数量，也不会丢失当前输入。

#### 未知条码学习

- 未知条码学习：商品资料查不到的条码可在有采购单 / 无采购单 / 联合收货 / PDA 收货时人工学习到某个商品，之后同码按该商品识别并在明细标「学习匹配」。商品资料始终优先，学习仅兜底；按公司 + 货主 + 仓储共享；设置 →「商品资料」可查看、搜索、删除、导出 CSV。

#### 操作记录

- 新增「操作记录」页：电脑和 PDA 的扫码加数、改数量、删除明细、物流单号增改删、挂起 / 结单 / 删除、入库请求与结果（失败也记）、登录 / 切换账号、设置修改等都会留下审计记录，含操作前后数量和来源设备；可按时间、设备、操作类型、采购单、SKU 筛选，服务端分页，支持 CSV 导出；收货明细弹窗可「查看此单操作记录」。默认保留 180 天（可设 7–3650 天），独立保存在 `operation_log.db` 并纳入备份（恢复备份时保留当前操作记录，不会被备份覆盖）；不记录密码、Cookie、验证码或令牌，记录写入失败不影响业务操作。

#### 物流单号提示

- 普通（有采购单）收货扫描 / 输入新物流单号时，会只读检查「无采购单收货」中是否已登记同一单号（忽略首尾及中间空白、不区分大小写，完全一致才算）。命中**未绑定采购单且未提交入库**的登记时，先弹出确认框（登记时间、件数 / SKU数、当前状态），**此时尚未建立物流子批次**：选「去无采购单绑定」直接打开该登记，不会留下空子批次；选「仍在此处收货」则照常建立，本页面会话内同一单号不再重复提示。若该登记已绑定**本采购单**，同样提示“请勿重复收货”；绑定其他采购单或已提交入库的登记不提示。已在本单建过的物流单号补扫不再检查。

#### 审查 P1 修复

- PDA 不再驱动电脑端录像：PDA 扫物流单号 / 扫商品不会让电脑端开始、切换录像或更新录像旁注；PDA 扫挂起单的物流单号时只建物流子批次，不再把它设为「当前收货」，电脑端正在收的单子不会被挂起。电脑端扫码行为不变。

- 远程管理页历史筛选的日期范围改为「范围内有活动」：开单时间或任一物流单的首次扫描时间落在所选日期内才显示，不再出现范围内毫无活动的单子。
