# 盘点提交热修复 2.0.3

## 修复内容

- 修复库存盘点提交时 ERP 明确拒绝并提示“对象必须实现 IConvertible”的问题。
- 根因：ModifyStockByPackItems 的第一个参数必须是序列化后的 JSON 字符串；旧版直接传入了数组。本版按官方页面 JSON.stringify(rows) 的参数约定发送。
- 直接改数量、+1、-1 共用已修复的提交接口。选择货主、仓库公司、附属仓及唯一仓位/批次明细的保护不变。
- 仍先预览，再确认，提交后回读核对；结果未知时不会自动重复写入，防止重复加减。
- 本次只改电脑端 Python 服务与回归测试，不改变 PDA 页面或原生代码；原 PDA 2.0.2 APK 可继续使用。

## 已执行的真实测试

经用户明确授权，只测试了“至臻测试货主 / 东莞至臻 / 主仓”的 test2 商品，仓位 TEST-1-2。

| 步骤 | 结果 |
|---|---|
| 原版参数复现 | ERP 明确拒绝，独立回查仍为 1000 |
| 修复后 +1 | 1000 → 1001，提交后回读及独立查询一致 |
| 修复后 -1 恢复 | 1001 → 1000，提交后回读及独立查询一致 |

**测试结束时已恢复原数量 1000，未操作其他商品。**

此次真实验证运行的是生产 InventoryService / InventoryAPI / JstClient 调用链，不是实体 PDA 点击验收。真实写入仅限上述主仓正式仓位；暂存位和其他仓库的覆盖使用隔离模拟数据，不表示已在实际仓库逐项写入验证。

## 升级方法

1. 先核实旧版未完成的盘点/入库操作。旧版如果明确显示 IConvertible 拒绝，不是成功；重新查询实时库存，再重新预览操作。若显示“结果未知”，先查 ERP 和异常记录，不要盲目重试。
2. 关闭旧主机程序，确认后台服务也已退出。启用 PDA 时仅关闭网页不会退出主机；先停用 PDA，再关闭程序。不要同时运行新旧主机写同一个 data。
3. 停机后备份原程序旁的整个 data 文件夹。用本包“电脑端/扫码入库助手.exe”替换原 EXE；**保留原 data 和导出目录，不要删除数据库**。
4. 启动新版并重新登录。设置/备份版本应显示 2.0.3-inventory-wire。
5. PDA 已装 2.0.2 的不必重装。本包不重复附带 APK；主机重启会撤销旧授权，登录后重新生成配对资料并配对。

扫码与收货历史、商品本地缓存、配对二维码、通用暂存位选择、采购外商品及同码候选逻辑保持不变。其他使用方法见《PDA优化版2.0-使用与升级指南.md》。
