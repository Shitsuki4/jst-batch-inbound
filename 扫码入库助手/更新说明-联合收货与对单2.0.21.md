# 扫码入库助手 2.0.21 试用版

本版从 2.0.20 总量颜色版继续，新增收货优化与多采购单汇总。不恢复已取消的跨轮次分批总览。

## 这次新增 / 修复

### 1. 相似商品辅助排版
- 优先查找相似款完整数量组合，再处理一对一。例如：蓝色少6、红色多4、采购单外粉色2，可排在同组。
- 不同容量、包装或品类有明确冲突时不强行并排。右侧编码只出现一次，剩余项不丢失。
- 歧义可手动并排、解除或恢复自动；页面和差异图片使用同一分组。手动排版只在当前页面、当前明细内容下保留，重载页面需重新设置。
- 仅为对单参考，绝不合并SKU、抵消少收多收或替你认定错发。大量明细超出组合搜索上限时完整显示，不保证自动找到所有组合。

### 2. 已匹配采购单完成归档
- 采购单跟踪“已匹配”卡片增加“标记完成”，填写可选备注后进入“已完成记录”。
- 完成记录可“转回已匹配”；后台核对不会立即把人工重开的记录顶回完成。
- 手动完成只是本地跟踪归档，不是ERP库存确认，也不是把ERP采购单改为完成。完成后来源变化会提示复核。

### 3. 无采购单登记改为普通收货式
- 输入首个物流单号 → 创建收货批次 → 扫商品并确认数量。
- 一个批次可继续扫其他物流单号；每件商品仍记到当前选中的物流单。
- 支持手动登记、明细编辑、暂存对单、退出后从历史继续；数量未确认 / 正在保存时阻止误切换。
- 后续请先在ERP按实收明细手工建立采购单，再在助手回填采购单号并核对；主历史可按回填采购单号或物流单号找到记录。
- 本版没有新增“助手自动创建ERP采购单”的功能。已有提交锁定规则保持不变。

### 4. 多采购单 + 一个整票子母件 + 汇总对单
- 主界面新增“多采购单合并收货”入口，输入多张采购单与母单 / 整票号，人工确认属于同一票。
- 支持同一公司账号、同货主、同仓库公司的1～30张采购单。采购单不能重复计入；读取失败或空明细拒绝创建，未知数量标记待核实，不会当作零收齐。
- 不要求预知每个子件装什么。每到一个子件，扫描其物流号、人工确认所属母单，再登记里面的实际商品。
- 汇总应收固定为创建联合批次时各采购单的“采购量－ERP已入库量”（最低0），实收为本联合批次真实物流明细之和。初始采购快照和可刷新的实时采购明细分开展示。
- 提供汇总对单、暂存并对单、差异横向对照、全量颜色表、复制图片 / 失败时保存图片、CSV导出。
- 同SKU出现在多张采购单时，入库前必须明确填写归属和数量，不按比例或顺序偷偷分配。只有唯一采购归属时界面才预填，仍需你确认。
- 两种入库方式：仅采购范围内编码；全部实收编码（组外编码也需要你指定采购归属）。随后逐张采购单生成独立的待入库草稿，不混成一张ERP采购入库单。
- 分配后数量被占用，退出 / 重启不会重复可用。未提交分配可取消后重分；已提交 / 结果待核实的份额不能解锁重建，应核查并继续原单。部分成功时保留成功部分，只处理其余部分。
- 首版联合模式限电脑网页；PDA仍2.0.8，只保留原有普通收货能力。不能将既有普通 / 无采购单批次一键转换为联合批次。

### 5. 历史搜索结果可关闭
- 采购单查询、物流查询各有“关闭结果”，保留关键词，不删除明细、不结单、不退出服务。
- 关闭后迟到响应不再重开。详情的×、底部关闭与Esc均可用。
- 数量未提交 / 保存中 / 保存失败时保留输入并提示先保存；可移开焦点或按Enter保存，失败后按Enter重试，成功后可关闭。

## 保留原有行为
- 普通收货“暂存明细继续对单”、按实收入库时的双选、初始采购单快照、实时采购明细及总量颜色均保留。
- “仅显示差异”的展示方式保持；相似款仅优化其中的并排顺序。
- 应用图标沿用已美化版，服务心跳暂停不退出、日志和单实例保护沿用稳定性修复。
- 不会自动确认ERP库存；不新增写价格、成本或供应商的操作。

## 升级与回滚（务必执行）
1. 先退出旧助手，确认旧服务已停止。不要同时用新旧版操作同一份data。
2. 备份旧EXE以及同目录下**完整data文件夹**；推荐额外备份整个旧程序目录。
3. 将本包“电脑端/扫码入库助手.exe”放入原程序目录，替换旧EXE，保留原data。也可先在复制的测试目录使用，但不要对同一批实收重复生成ERP入库单。
4. 首次启动会保留原数据库并进行必要兼容升级；联合收货新增data/joint_receipts.db，并已加入自动备份名单。
5. 若回滚2.0.20，必须退出新版，同时恢复**升级前EXE＋整份升级前data**。不能只换EXE，也不能把新旧data中的单个数据库混用；回滚会丢弃升级后本地改动，请事先导出并人工核对ERP已生成单据，不能重复建单。

## 验证范围与试用提醒
本版使用临时数据库、Fake ERP和本机浏览器测试，没有连接你的真实ERP改 / 建单，没有使用生产收货数据。测试能验证既定流程与防重机制，不代表已覆盖所有真实商品名称和ERP异常。请先选一票小批量核对；多采购单正式生成前仔细检查每个编码的分配、采购单、仓库和数量。
