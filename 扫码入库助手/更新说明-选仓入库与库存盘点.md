# 选仓入库与库存盘点版（2026-10-01）

## 1. 按实收生成入库单：已补齐选仓

1. 创建收货批次时先选择正确的**货主和仓库公司**，例如「品秀供应链 → 东莞品秀刷货仓」，不要使用「所有商家」。
2. 在收货页或记录查询中打开「按实收生成入库单」。窗口显示该批次原货主及仓库公司，后续切换首页下拉框不会改变这份历史上下文。
3. 从原上下文的仓库清单中选择主仓、进货仓、次品仓或自定义附属仓。可选项以当前账号实际权限和 ERP 配置为准，不硬编码仓库ID或名称。
4. 选仓后重新预览实收，再点击确认。仅包含尚未关联入库单的正数实收物流子批次，同 SKU 合并。
5. 程序创建空草稿、保存目标仓库、添加实收数量并回读核验货主、仓库公司、源采购单、仓库和明细数量。成功记录显示目标仓库。

**生成的是「待入库」草稿，不自动确认入库。** 请在 ERP 检查商品、数量、仓库和成本后正式确认。
货主（owner_co_id）、仓库公司（authorize_co_id / wms_co_id）、附属仓（wh_id）是三个不同层级；渠道仓 lwh_id 不作为附属仓使用。

- 所有商家／所有仓库（2147483647）禁止写入；原批次上下文不完整时停止，不擅自换用当前登录公司。
- 创建结果不明：保留占用并禁止重建，需核查后关联原空草稿或数量一致的原单。
- 已有单号但换仓、加商品或改数量中断：只继续同一张原单，不重新开单。
- 已正式入库或取消的单据不会被自动换仓；与目标仓库不符则停止。
- 升级前已有的持久化入库任务保持原协议、原仓库，不擅自替历史任务选仓。

## 2. 新增独立「库存盘点」页

### 操作

1. 进入顶部「库存盘点」，选择**货主 → 仓库公司 → 库存仓库**。
2. 选择「商品编码」或「仓库条码」，扫描/输入单个完整编码并回车查询。
3. 结果显示实时数量、冻结量、仓位/箱、生产批次（如有）及库存明细ID。**明确选择一条库存明细**，不自动合并同 SKU 的不同仓位，也不默认挑第一条。
4. 选择操作：
   - **直接改为**：输入 100，则该明细目标数量为 100，不是增加100。
   - **增减数量**：输入 1 / +1 增加1，输入 -1 减少1；支持其它正负增量。
   - **+1 / −1 快捷按钮**：切换到增减模式并填入数量，仍需预览确认，不会点击即写库存。
5. 点击「预览修改」，核对货主、仓库、商品、库存明细与「原数量 → 目标数量」，再点「确认修改这条库存」。
6. 程序提交前重新核对原数量，并在提交后回读。下一件商品重新查询选择。

**盘点确认会直接修改 ERP 库存（ERP 通过盘点流程处理），不是只保存本地记录。**
成功响应只返回布尔值，程序不编造远端盘点单号；本机记录保存操作标识、作用范围、原/目标数量和核对状态。

### 安全规则与边界

- 预览2分钟有效。预览或确认时发现数量变化就停止，不能把过期的 +1 应用到新库存上。
- 本地记录先落库再发出写请求；同一确认标识重复提交只读原结果，数据库索引保护同一库存明细的未决操作。
- 网络中断/重启后不自动重发。记录中的「仅回读核实」只查询，不改库存。
- 当前数量等于目标时标记已核对；不等于目标或记录身份变化时保持待核实并禁止再次盘点该明细。请先在 ERP 人工核查，勿通过删除本机数据库绕过保护。
- **ERP 接口没有条件更新/CAS或原子增减。** 提交前校验不能完全消除最后一刻的并发竞态；请安排同一库存明细不要被其它终端同时修改。
- 目标数量不能为负或超上限。未开启小数的仓库仅收整数；开启后最多4位小数。
- 补货暂存位、盘亏位、装箱出库位不支持直接修改；程序沿用 ERP 的禁改限制。
- 查不到库存明细时不创建新的 PackItemId；ERP 可能隐藏零库存记录，可去 ERP 库存页面处理。
- 仓库条码为 ERP 的 sku_code 精确查询；此盘点页不把款式编码、其它辅助码或模糊匹配结果自动当作 SKU。

## 3. 商品资料仍每6小时本地更新

原本的本地商品资料、离线优先扫码、缺码可选联网和手动更新均保留。
**商品资料缓存不等于库存缓存。盘点的查询、预览、提交复核和回读必须联网获取实时数量。**
后台6小时同步仅在程序运行且已登录时进行，关闭程序后不运行。

## 4. 升级和运行

- 先关闭旧程序，备份原来 EXE 同目录的整个 data 文件夹。
- 解压新版，用其中 dist/扫码入库助手.exe 替换旧 EXE，保留原路径旁边的 data 与导出文件夹。
- 不要用全新的空 data 覆盖旧数据；若迁移到新目录，请一并迁移备份的 data。
- 本次自动新增 inventory_op 表及防重索引；不删除原收货数据、入库任务或商品库。
- 压缩包不包含实际登录态、浏览器配置、抓包数据或业务数据库。

## 本地接口（便于维护）

- GET /api/inbound/options?sid=：原货主／仓库公司及可选附属仓。
- GET /api/inbound/preview?sid=&wh_id=：包含仓库的实收确认快照。
- POST /api/inbound/create：sid、wh_id、fingerprint、confirmed:true；resume 保持原接口。
- GET /api/inventory/partners、config、lookup、history：清单、规则、实时明细与本机记录。
- POST /api/inventory/preview：owner、auth、wh_id、code、code_type、pack_item_id、expected_qty、mode(set/delta)、value。
- POST /api/inventory/submit：token、confirmed:true；POST /api/inventory/verify：token，仅回读。
