# 当前版本：电脑端与PDA 2.0.4

新增未知商品收货后的“编辑资料”，生成入库仍强制核验商品资料。先读《更新说明-收货编辑与入库修复2.0.4.md》。

# 扫码入库助手 · 电脑版 2.0.3 / PDA 2.0.2

本次修复盘点提交时 ERP 报“对象必须实现 IConvertible”的参数类型问题，详见《更新说明-盘点修复2.0.3.md》。仅升级电脑端；已安装的 PDA 2.0.2 APK 无需重装，主机重启登录后重新配对。此前的二维码、暂存位、采购内外同码候选、编码显示/复制/字体优化及「设置 → 校验采购单明细」开关全部保留。

## 先看边界

- **Windows电脑是主机，PDA是局域网伴随端**，不是离线独立ERP。电脑运行、ERP已登录且网络可用时，PDA才能工作。
- **入库：按本地实收生成待入库单，不自动确认入库。** 货主/仓库公司沿用收货单，必须是具体商家而非“所有商家”；生成前选主仓、进货仓、次品仓或接口实际提供的附属仓。
- **盘点：预览并确认后直接修改ERP库存**。必须选具体货主、仓库公司、库存仓库及唯一库存明细。按仓位/批次逐条改，不擅自合并。
- 扫码枪使用**键盘输入模式，结束符Enter**。APK不包含相机扫码或厂商专有扫码SDK。最低Android 8.0，建议更新系统WebView；已在Android12模拟器验证，尚未在你的实际PDA硬件验收。

## 一、升级电脑端

1. 先在旧版处理完未核实的入库/盘点请求，关闭旧程序；不要同时开两个版本操作同一库。
2. 停机状态下把旧data目录完整复制到私有备份位置。目录可能包含浏览器登录信息/私钥，不要发送给他人。
3. 用发布包的「电脑端/扫码入库助手.exe」替换原EXE，保持原EXE旁的data目录，不要删除数据库。也可复制旧data到新EXE旁；目录需可写。
4. 启动新版。已有数据库首次进入2.0前做SQLite在线备份再迁移；备份失败会停止启动，先处理磁盘空间/权限/损坏问题，不要删库绕过。
5. 到设置确认商品库状态。首次更新完成前，可匹配采购明细。开启自动同步后，主机运行且已登录时每6小时更新商品档案；失败保留旧快照。**实时库存不缓存**；缺码联网兜底默认关闭，避免每扫一件等网络。

已打包EXE内置运行依赖，需Windows 64位及Microsoft Edge。关闭PDA功能时仍可只用电脑端。

## 二、电脑启用PDA

1. 登录正确ERP账号。打开收货单时先明确具体货主与仓库公司，例如你的「品秀供应链—品秀刷货仓」对应范围，而非所有商家。
2. 电脑和PDA接同一可信仓库Wi-Fi/局域网。关闭访客网络隔离；建议给电脑固定内网IP或DHCP保留。
3. 设置 → PDA局域网配对：选实际局域网网卡（不要选VPN虚拟网卡），端口默认8766，确认启用。
4. Windows防火墙只允许该EXE/所选TCP端口的**专用网络、局域网来源**。程序不自动修改防火墙，不要把整机防火墙关闭，也不要开公网映射。
5. 点「生成5分钟一次性配对资料」。每个码仅用一次，新生成的码替换旧码；每台PDA单独配对。
6. 电脑需保持运行、不要睡眠。启用PDA后关闭操作网页不会结束后台服务；重新打开电脑界面可在浏览器访问本机端口（默认http://127.0.0.1:8765，以启动日志为准）。停用时点「停用并撤销全部设备」。

## 三、安装并配对APK

1. 在PDA安装「扫码入库PDA-2.0.4.apk」。如系统询问，只允许你用于安装此文件的应用安装未知来源软件，装完可关闭该权限。
2. 打开APK，点进配对资料输入框，用支持二维码的PDA扫描枪扫描电脑上的配对二维码，结束符Enter会自动填入。也可粘贴整段JSTPDA1:资料后点「填入配对资料」，或手填HTTPS地址、64位SHA256指纹和8位配对码。此功能不调用相机。
3. 核对电脑地址/证书指纹，给设备起可识别名称，点「核对并安全配对」。指纹不符会拒绝连接，不要跳过核对。
4. 授权最长8小时，仅存内存。应用进程重启、返回配对页或部分系统重建场景需重新配对；ERP退出/重新登录/换账号或电脑重启会撤销授权。设置可查看并单独撤销设备。
5. APK仅申请联网权限；不把ERP密码/cookie复制到PDA。页面资源内置，业务请求通过原生HTTPS固定证书指纹通道传输。

若连接失败：查双方网络、IP/端口、专用网络防火墙、设备日期时间、配对码是否过期。电脑IP变化需停用后选新网卡重新启用、重新配对。别在PDA填127.0.0.1——那是设备自己，仅供开发测试。

## 四、PDA收货与建入库单

1. 新采购单先在电脑端按正确货主/仓库公司打开；PDA从已有收货单列表选择。
2. 扫描物流单号并确认，或选择该收货单下已有物流子批次。
3. 扫商品编码/条码，先识别商品；同码多候选必须人工明确选择。输入本次实收数量并确认，才会累加到本地实收。
4. 本地实收核对完成后点「按本收货单实收生成待入库单」，选实际入库仓库，确认货主、商品、数量。只汇总尚未生成的物流子批次，已关联批次锁定，补收用新物流单号。
5. 到ERP核对草稿仓库、成本、数量，人工正式确认。没有自动ConfirmBatch调用。

**断网/响应丢失**：界面会锁住继续收货，保存请求编号。重新配对/打开同一主机后，先点「只查询上次请求结果」，查询本地已保存结果，不重复累加。只有主机明确未收到时才允许同编号人工重发。结果不明时查看电脑实收及异常记录，人工核实并留备注后才能结束本机等待；原请求仍保留，不会自动重放。未核实前不要清应用数据、换设备重新扫描同一件。

## 五、库存盘点

1. 选具体货主、仓库公司、主仓/进货/次品等实际仓库，再选「全部位置（含暂存位）」「正式仓位」或接口支持的「通用暂存位」，输入完整商品编码或仓库条码。
2. 查询实时库存，明确选择一条仓位/批次明细。
3. 直接改为：输入目标绝对数量（例如100）；增减：输入+1、-1或其它增减值。快捷+1/−1仅填值，仍需预览与确认。
4. 预览原数→目标数，核对范围后确认。预览2分钟有效，提交前再查旧数量；旧数量变了会阻止提交。
5. 开启「连续盘点」后，成功回读才清空编码并回到扫码框。仅保留增减值；绝对数量每件清空，防止把上一件数量带到下一件。可关闭声音。
6. 结果不明只能「仅回读核实」，不自动重发增减。回读目标一致不是对并发的绝对证明：ERP没有原子增减/CAS锁，请勿让其它终端同时改同一明细。

## 六、异常中心与备份

- 「异常与记录」默认显示待核实记录，可取消筛选看完成记录；入库可查看原单，盘点可只读回核。备注只追加，不解锁、不覆写历史、不重发业务。
- 电脑端可导出CSV，已处理公式注入字符；文件仍含业务/操作员信息，请私下保存。PDA不开放桌面设置、登录管理、数据库和导出接口。
- 设置可手动备份；后台每5分钟检查当天是否已有完整备份。只备份jst.db、catalog.db，附完整性检测和SHA256清单，**不含扫码浏览器目录或PDA私钥**。
- 备份在data/backups；失败保留原库，不自动清理旧备份。定期检查磁盘并复制到另一块盘/受控备份存储；同盘备份不能防硬盘损坏。
- 恢复必须先停用PDA并关闭电脑进程。先额外保存当前data完整副本；选manifest显示complete=true且哈希一致的备份，将两份数据库恢复到新的独立运行目录，避免混入旧的-wal/-shm文件。重新登录、配对。
- **恢复旧库会回退防重和操作日志**，恢复前后必须与ERP核对备份之后的入库/盘点，不能把回退的本地记录当成“未操作”再次提交。不提供一键自动恢复。

## 七、验证范围与后续

2.0.2已覆盖12套离线回归、模拟接口、400px页面、EXE实包与APK资源/签名校验。本次未做实体PDA或新版APK模拟器操作验收；旧版原生连接曾在Android12模拟器验证。未用真实账号执行新建入库/修改库存；首次实际使用先用一小批核对，再扩大范围。

本版不含：离线ERP写入队列、相机扫码、厂商扫码SDK、良品次品明细自动拆分、多人任务认领、ERP级原子并发锁。多个设备的操作保留各自记录，但仍应安排好库存明细的分工。

## 源码构建

电脑：Python 3.11+，python -m pip install -r requirements.txt pyinstaller，python -m PyInstaller build_exe.spec --noconfirm。
APK：JDK17、Android SDK build-tools36.0.0/platform android-36.1，设置JAVA_HOME和ANDROID_HOME，再运行python android-pda/build.py。无需Gradle。构建脚本默认从相邻「扫码入库助手/app/web」取共享资源。
签名密钥在源码工作区之外的android-private目录，发布包不包含。维护者必须私下备份原签名密钥；换签名将无法覆盖安装老APK。重新生成不同签名的包不能视作同一更新。

EXE诊断：扫码入库助手.exe --self-test，仅在临时目录生成TLS证书并退出，不连接ERP、不加载业务库。测试入口与真实生产环境严格分开。
