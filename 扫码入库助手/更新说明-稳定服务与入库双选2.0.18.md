# 服务稳定性与入库双选 2.0.18 试用版

基于 2.0.17 更新，保留「暂存并对单」、采购单工作台和扫码过滤等既有功能。

## 1. 修复开一会儿服务自行关闭
- 原因之一已经复现：旧版收到网页心跳后，超过 30 秒没有新心跳便直接退出；浏览器最小化、后台节流、电脑睡眠或页面暂时无响应都可能触发。
- 本版取消心跳失联退出。心跳只记录连接状态，网页关闭或不再发送心跳时，本地服务仍保持运行，不关闭收货数据库。
- 同一数据目录重复双击本版 EXE，会复用已有服务并打开本机页面，不另起一个操作同一数据库的服务。
- 需要退出时：先等待「保存 / 生成入库」等操作完成，再关闭服务控制台，或在服务控制台按 Ctrl+C。**网页顶栏的退出账号，不等于停止服务。**
- 新增 `data/logs/service.log`，记录启动、心跳暂停/恢复、正常停止及未处理异常。单文件最多约 2MB，保留 3 个轮转备份。日志只在本机，可能包含账号名、商品编码和单号等业务信息；外发排查前请检查并脱敏。
- 本次解决的是已复现的心跳误退出路径；不保证能阻止系统关机、杀毒软件终止进程、硬件故障等外部终止。

## 2. 点击「按实收生成入库单」后，选择两种方式
原设置里的「校验采购单明细」不再显示。普通收货 / 记录中的入库入口，每次打开都先选方式，随后选仓库、核对数量，再确认生成。

### 方式一：仅采购单内编码
按实收数量生成入库草稿，采购单没有的商品编码不加入本次单据。
- 对照本轮保存的采购单编码精确判断，不按相似名称替换编码，也不受历史 matched 标记或旧设置开关影响。
- 预览明确列出「本次不加入」的商品、物流单号、数量；这些明细保留在本地，**没有被算成已入库**。
- 如果只收到单外商品，则没有可生成的单内明细，不会创建空单。
- 生成前仍读取最新采购单校验所选编码；若采购行已被删除、存在重复编码或商品资料不存在，停止生成，要求重新核对。

### 方式二：全部实收编码
按实际收到的商品和数量生成入库草稿，采购单没有的编码也加入。
- 单外商品必须存在于当前货主的商品资料中；不是任意未知编码都能入库。
- 不修改采购单，不替换商品编码，不写价格、成本或供应商；成本及单外商品价格请在聚水潭核实。

### 分次生成和防重复
- 先选「仅采购单内编码」，后来再选「全部实收编码」，只会处理原来没有提交的明细，已处理商品不重复生成。
- 部分生成后，物流批次仍保持编辑锁；排除行保留且能另行生成，但不支持在已锁物流下直接改数量、删行或继续补扫。补收请新建物流子批次。
- 已有「创建结果不明 / 数量待核对」记录时，必须先核对或继续原单，不能切换方式另建一张。
- 原单续作固定使用原快照，不受新选方式或旧全局设置变化影响。
- 老版本的整物流批次入库记录保守沿用原锁，不猜测历史剩余行，不自动重新生成。

**两种方式都仅生成聚水潭「待入库」草稿，不会自动确认库存。**
独立无采购登记、采购工作台仍保留原有授权、采购状态和来源校验流程，不放宽其权限。

## 3. 界面与图标
- EXE 增加多尺寸「扫码纸箱 + 完成勾」图标；登录页、顶栏、网页标签图标统一。
- 登录输入框、按钮、入库方式卡片及预览重新排版；窄屏下选项纵向显示。
- 差异语义色保持：采购单外灰色 #e0e0e0、差异黄色 #fff176、收齐绿色 #a5d6a7。
- PDA 仍为 2.0.8，不需要重装、不改签名。

## 4. 升级方式（重要）
1. 先关闭旧版服务控制台；旧版程序不参与新版的同目录单实例保护。
2. 备份旧 EXE 和完整 `data` 文件夹。
3. 用本包 `电脑端/扫码入库助手.exe` 替换旧 EXE，保留原位置、保留原有 `data`，**不要把空 data 覆盖到旧目录**。
4. 启动时自动做版本前备份和明细关联结构迁移。若需回退，请恢复升级前 EXE 与整份升级前 data，不要将新库随意交给旧版继续处理。
5. 先用少量可核对的实收明细试用两种方式，再到聚水潭核对单号、商品、数量、仓库及价格。

## 验证边界
全部建单相关测试使用临时数据库与模拟 ERP，未对真实聚水潭建单、改单或确认库存。已执行打包 EXE 的默认配置失联测试、入库分次防重/重启恢复、HTTP 并发、真实页面和既有功能回归。真实账号权限、ERP日期字段/采购完成状态和成本价格继承仍需实际试用核实。
