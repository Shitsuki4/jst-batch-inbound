# 扫码入库助手 2.0.9：差异筛选与一键复制

## 这次改了什么

### 1. 收货结单：默认只看差异
- “收货已完成 · 差异校验结果”默认勾选“仅显示差异（含待核实）”。
- 已收满商品隐藏；少收、多收、未扫码、计划外有实收和数量待核实的商品保留。
- 取消勾选即可查看全部。全部已收满时明确显示“全部已收满，无差异”。没有商品数据时显示“暂无商品明细，无法校验”，不会冒充已收满。
- 商品仍显示编码、商品名、69码/条码或辅助码，以及采购数/ERP入库数、本轮应收、本轮已收和差额。

### 2. 两个独立复制按钮
| 按钮 | 图片包含什么 |
| --- | --- |
| 复制完整结果（含已收满） | 本轮全部商品，包括已收满商品 |
| 仅复制差异 | 少收、多收、未扫码、计划外有实收及待核实商品 |

- 两个按钮不受当前“仅显示差异”勾选状态影响，也不改变当前显示范围。
- 一次写入剪贴板的内容包括采购单号、外部单号文字及对应的PNG结果图片；同时提供HTML格式供支持图文粘贴的软件使用。
- 图片顶部也保留两种单号、轮次、开始时间及范围，避免只粘贴图片时丢失单号。
- 图片从全部报告数据生成，不是截图当前可见区域，滚动区下方的商品也会带上。
- 报告顶部的本轮已收/应收始终是全轮、所有物流单合计，不是当前筛选行的小计。
- 超过单图30000像素高度时明确报错，不静默截断或复制不完整结果；可改用仅差异，或使用原有明细导出核对。

**粘贴兼容性：** 实测本机Edge可同时写入PNG、纯文本和HTML。接收软件决定采用哪种格式，不保证每款微信/QQ/办公软件都把文字和图片作为两个独立内容粘出。如果只粘出图片，单号也在图片里面。

**复制失败时：** 不显示“已复制”；页面提供“保存结果图片”、图片预览和“单独复制采购单和外部单号”。可以保存PNG后发送。

### 3. 查询历史
- “查看明细与差异”同样默认只显示差异，可取消勾选看全部，支持相同的两个复制按钮。
- 筛选作用于本轮收货核对报告，下面原有物流单逐行收货明细和旧口径折叠区保留，历史数据不删除。
- 按采购单查询里的本轮核对默认完整显示，也支持仅差异切换和复制。

## 数量逻辑不变：与2.0.8一致
- 本轮应收 = 本轮开始时采购数 − 当时ERP已入库数（不小于0），本轮开始后固定。
- 本轮已收 = 当前这一轮所有物流单的本地收货合计。
- 例如开轮时采购10、ERP入库6，本轮应收就是4。
- 如果开轮时采购12、ERP入库2，本轮应收10；这一轮收了4后即使ERP刷新变成入库6，本轮仍显示应收10、已收4、还差6，不重复扣减。
- 结单只结束本轮本地收货，不等同于ERP已确认入库。没有新增自动入库或确认操作。

## 升级方法
1. 结束当前电脑端操作，关闭旧程序。
2. 将“电脑端/扫码入库助手.exe”替换到原电脑端目录，保留原data和导出目录，不删除数据库。
3. 重新打开程序；新版本会按原有机制做升级前备份。
4. 确认设置/备份里的版本为2.0.9-difference-report。不要仅在旧程序仍运行时覆盖文件后继续使用旧窗口。

**本次只有电脑端报告更新。PDA仍为原2.0.8，已经装好2.0.8的设备无需重装。** 为完整交付，压缩包继续附带原签名的2.0.8 APK；其文件未修改，电脑端内置下载包也仍为2.0.8。

## 安全范围
本次使用临时数据库、FakeJst和独立无头Edge验收，未操作真实采购单、入库单或真实ERP登录。升级不清除旧收货记录，不关闭留作接口观察的浏览器。本包不含用户数据库、登录资料、浏览器配置、抓包和Android签名私钥。
