# 扫码入库助手 2.0.19 试用版

在已交付 2.0.18 基础上，只调整「记录查询 → 收货明细与差异」以及采购单查询的对应对照区域。

## 按你的要求分为两种显示

### 勾选「仅显示差异」
保持原来的对单界面、相似品并排和差异计算不变，仍按本轮起始应收核对；不按实时采购总量改写本轮目标。

### 取消勾选「仅显示差异」
改为旧版采购总量对照的五列表：商品编码 / 商品名称 / 采购总量 / 实收 / 差异。
- 每次打开明细、查询采购记录时，读取实时采购明细；弹窗也可点「刷新实时采购明细」。
- 采购单改数量、改名称、增加或删除编码，成功刷新后反映到这张表。
- 实收是当前这条记录下各物流单号的合计，不混入同采购单其他收货轮次。
- 修改物流数量成功后，实时总量表和初始快照表的实收会一起更新；保留勾选状态及快照展开状态。
- 表中显示最近成功获取时间；网络/登录/权限异常会明确提示，不把旧数据冒充刷新成功。不会在后台不停轮询采购单。
- 在这些记录区域，「复制完整结果」复制实时采购总量的完整图文；「仅复制差异」仍复制原本轮对单差异。结单、暂存对单的复制保持原样。

## 「历史采购总量对照」改为「初始采购单快照」
- 新查询的采购单在首次成功查询并建立收货记录时，单独保存采购编码、名称、规格、条码、数量等明细。
- 按采购单号 + 货主公司 + 仓库公司区分，避免同号跨公司混淆。
- 后续 ERP 改单、刷新、继续收货、新建收货轮次、重启或删除后重新查询，都不会覆盖这份采购快照。
- 固定的是采购明细，不是实收：实收始终按当前这条记录的物流明细计算。更改、删除明细或删除物流批次后，重新读取的实收随之变化。
- 实收出现快照以外的商品时单独列为采购单外商品，不把它追加为初始采购商品。
- 商品以精确 SKU 汇总，兼容旧 RAW 编码行；相似名称只排版参考，不合并编码或抵消差额。缺失数量显示待核实，不当作零。

### 旧数据的真实边界
旧版没有专门保存这份采购单级快照。升级时仅使用**最早仍保留的收货轮次起始快照**，并在界面注明来源；如果更早记录已删除，无法恢复那次数据。没有起始快照或数据损坏的旧记录，会明确显示「初始采购明细缺失」，不会用当前实时明细冒充首次快照。

## 升级方法
1. 等待保存、生成入库结束，关闭旧版服务窗口。
2. 备份旧 EXE 和整个 `data` 文件夹。
3. 将本包「电脑端/扫码入库助手.exe」替换到原程序目录，保留原 `data`。
4. 启动 2.0.19。不要让新旧版本同时访问同一份数据。
5. 需要回滚时，恢复升级前 EXE **及整份 data**，不要仅换回旧 EXE。

此次数据库新增独立初始快照表；不删除或重算原实收记录。PDA 仍为 2.0.8，无需重装。

## 继续保留
2.0.18 的心跳失联不退出、运行日志、同目录重复启动复用、每次入库双选和新图标；2.0.17 的「暂存并对单」。
两种入库方式仍只生成待入库草稿，不自动确认库存，不写价格、成本或供应商。

测试全部使用临时库及模拟 ERP；未操作真实 ERP 建单、改单或库存。真实账号权限与 ERP 成本继承未实号写验证。详见「发布验证-2.0.19.md」。
