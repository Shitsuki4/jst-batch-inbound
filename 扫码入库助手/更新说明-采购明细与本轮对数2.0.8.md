# 扫码入库助手 2.0.8｜采购明细与本轮对数

## 本次调整
- 恢复紧凑的采购明细表：**商品信息 / 本轮应收 / 本轮已收 / 差额**。
- 商品信息保留 **商品编码、商品名称、69码/条码、辅助码**；ERP同时提供条码和辅助码时都显示，支持复制。商品名与编码即使相同也不会互相省略；规格与商品名完全相同时不重复显示规格。
- 商品信息下显示 **采购数 / ERP入库数**，不再重复一遍商品名。桌面采购面板加宽，PDA采用窄屏换行，不截断编码。
- 采购数量与ERP入库数量来自最近一次成功获取的采购明细；后台跨端同步只更新本地收货，不自动轮询ERP。需要最新ERP数量时点“刷新采购状态”（PDA点刷新）。失败保留上次成功数据和失败提示。

## 数量怎么对
“本轮”指一张收货记录，其下面可以有多个物流单号，不是当前物流单号。

| 字段 | 口径 |
| --- | --- |
| 采购 / 入库 | 最近一次成功获取的ERP采购数量 / 已入库数量 |
| 本轮应收 | 本轮开始时的采购数量减去ERP已入库数量，最低为0；本轮内不自动改变 |
| 本轮已收 | 本轮所有物流单号的本地实收合计 |
| 差额 | 少收显示“还差”，相等显示“收满”，多收显示“多收” |

例：开始时采购12、ERP入库2，则本轮应收10。两个物流单各收2，本轮已收4、还差6。
后续ERP入库数变成6，商品下显示“采购12 / 入库6”，本轮仍是“应收10 / 已收4 / 还差6”，避免把同一批货重复扣减。
ERP数量改变会提示核对相关入库单。程序不会仅凭ERP余额变化或关联了草稿就认定本轮已确认入库。

## 暂停、结单与旧数据
- 切换物流单、退出后继续、同单重新查询：未结束的同公司收货轮次继续复用，不清零、不重置起始数量。
- 已结单的记录不再重新激活。再次创建同采购单时，需要确认“开始新一轮收货”；新一轮按当时ERP余量计算，历史实收留在旧记录，不混到新轮。
- 新开一轮前先核对旧轮在ERP的入库处理，**未处理完的旧货不要重复扫码**。
- 2.0.7及更早的历史记录没有可靠的本轮起始基线，因此应收和差额标为“待核实”，原收货数量、物流单和入库关联保留；不会按0或猜测补算。
- ERP缺失数量、开始后新增商品等也会明确显示待核实。旧的采购总数对照及ERP关联汇总保留在折叠区，与本轮口径分开。

## 升级
1. 在旧版设置中备份，退出正在运行的电脑端；**保留原data文件夹**，不要卸载清数据。
2. 将压缩包“电脑端”里的EXE放回原程序目录后启动（可先另存旧EXE）。本版还会执行升级前备份和新增字段迁移，不重写旧记录的数量。
3. PDA安装包与电脑端都升级到2.0.8。APK沿用原应用ID和签名，可覆盖安装；不要卸载清空配对资料。需要时重新配对。
4. 首次使用请核对一张小单。只有在核对后，才实际提交入库。

## 验证边界
本版采用临时数据库、FakeJst和独立无界面浏览器进行离线回归；没有创建、确认、取消任何真实ERP单据，没有改动用户数据库。实体Android6设备和扫码枪仍需现场验收，转译资产浏览器测试不等于真机验收。
原2.0.6、2.0.7发布包和签名身份保留。原测试用ERP浏览器未关闭，也没有新增自动抓包任务。
