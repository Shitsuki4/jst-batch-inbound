# 扫码入库助手（聚水潭）

基于已抓取的聚水潭内部接口，做的一个**聚水潭查询 + 本地收货 + 按实收生成待入库单**的轻量扫码收货客户端。

> 电脑版 2.0.12（标准色加深显示）/ PDA 2.0.8：原生 HTML/JS + 轻量 Python 服务。PDA证书生成使用 cryptography、配对二维码使用本地 qrcode；Windows EXE 已内置依赖，无需安装 Python。
> PDA是局域网伴随客户端，电脑需保持运行。启用PDA后关闭网页不会结束主机服务，请先在设置停用。
> **本次更新见《更新说明-标准色加深显示2.0.12.md》，升级先读《PDA优化版2.0-使用与升级指南.md》**；入库生成的是待入库单，盘点确认则直接修改库存。

## 一、启动

双击 **`启动扫码入库.bat`**，浏览器会自动以独立窗口打开操作界面。

命令行启动（等价）：

```bash
python -m pip install -r requirements.txt  # 源码首次运行，建议 Python 3.11+
python app/server.py          # 默认 8765，被占用时自动顺延端口
set JST_PORT=9000 && python app/server.py
```

### 打包成 exe（免装 Python，双击即用）

不想在每台电脑装 Python 时，可以直接用打进好的单文件 exe：

```bash
双击 打包exe.bat                  # 或：pyinstaller build_exe.spec --noconfirm
```

产物：**`dist\扫码入库助手.exe`**（单个文件，体积以发布包为准）。

- **单文件**：整个 exe 拷到任意目录双击就能用，自带 Python 运行时，**目标机无需装 Python**。
- **数据放 exe 同目录**：首次运行自动在 exe 旁边生成 `data\`（数据库 `jst.db`、扫码登录配置
  `edge-login\`、诊断日志 `diag.log`）和 `导出\`。换电脑时把 exe + 这两个目录一起拷走即可，
  重装/替换 exe 不会丢数据。
- **前端资源（web）打进 exe 内部**，随 exe 走，不需要额外拷文件。
- 仍然需要目标机装有 **Microsoft Edge**（界面靠 Edge 的无边框窗口打开）。
- 保留控制台窗口，便于查看运行日志与「未找到 Edge / 登录失败」等提示。

> 源码：Python 3.11+，先安装 requirements.txt。打包另装 PyInstaller：
> `python -m pip install -r requirements.txt pyinstaller`；然后运行 `python -m PyInstaller build_exe.spec --noconfirm`。

## 二、界面与操作

### 1. 登录（三种方式）

登录页顶部有三个标签：**账号密码 / 短信验证码 / 扫码登录**。

#### ⓪ 常用账号（记住账号名，不存密码）

登录成功后本地会记下这次用过的**账号名**，下次打开登录页在账号框下方以「常用账号」
标签列出，**点一下即填入**账号（再手输密码即可）；标签右上角 × 可把不用的账号移出列表。
只存账号名、**绝不存密码**，登录态仍只留在内存里（关掉程序即失效）。

#### ① 账号密码（含图形验证码）

走 `api.erp321.com` 的 `UserApi/WebLogin/Passport`，会话 cookie 由响应体里的 `cookie`
对象落地（不是 Set-Cookie），并自动带上页面的风控指纹参数（`j_d_3` / `v_d_144`，
由页面加载的京东与阿里云盾 SDK 生成，取不到则按官方格式本地合成）。

服务端返回 **`10003`** 时表示这次必须过图形验证码：界面会自动展开「验证码」一栏、
从 `https://www.erp321.com/ValidCode.aspx?channel=login&id=<账号>&t=<时间戳>` 拉图，
点击图片可换一张，验证码回填进 `verifyCode` 字段再提交。
这张图会给会话种下 cookie，客户端会自动带着去校验。

#### ② 短信验证码

| 步骤 | 接口 | 说明 |
|---|---|---|
| 下发 | `POST api.erp321.com/usercenter/AuthApi/WebLogin/SendVerificationV2` | body `{data:{mobile[,suffix]}}`，返回 `cId` / `prefix` / `isLoginId` |
| 校验登录 | `POST api.erp321.com/usercenter/AuthApi/WebLogin/VerificationV2` | body `{data:{mobile,verificationCode,suffix,cid,j_d_3,v_d_144}}` |

- `cId` 由服务端内存持有，**不经过前端**，避免被篡改或复用；用完即清。
- 若返回 `isLoginId=true`（该手机号绑了多个账号），界面会多出「手机尾号」一栏，
  用户补**手机号后两位**后再发一次——对应官方网页上「验证已绑手机号」那一步。
- 下发接口官方实现**不带**风控参数（只有校验那一步才带），补上也无影响，已保持一致。
- 手机号没绑账号时服务端返回 `301046` 且文案伪装成「账号已禁用，请咨询在线客服」，
  界面会补一句人话解释。别被原话误导，那不是风控。

#### ③ 扫码登录（微信 / 钉钉）

聚水潭官方 PC 登录页的扫码是**第三方 OAuth**（微信 appid `wx9dec215f86304fe9`、
钉钉 ddLogin），授权回调落在 `jstlogin.erp321.com`，**会话 cookie 由浏览器写入 `.erp321.com` 域**，
所以必须把会话从浏览器「取」回客户端，流程是：

1. 点「微信扫码登录」/「钉钉扫码登录」→ 用**独立** Edge 配置目录
   （`data/edge-login`）+ 独立调试端口打开 `https://www.erp321.com/login.aspx`
2. 在页面**右上角点「扫码」图标**切换，选好微信 / 钉钉，手机扫码确认，直到进入聚水潭主页
3. **无需任何操作**——本工具每 2 秒自动检测一次登录态，命中 `u_id` 后自动关掉扫码窗口、
   直接进入系统；万一自动检测没生效，还有「扫完没反应？点这里强制取回」按钮兜底

关键实现（CDP 主路径 + SQLite 回退）：

- **为什么不能只读 Cookies 库**：Chromium 的 cookie 落盘是异步批量提交（约 30 秒一个周期），
  而且**会话级 cookie（聚水潭的 `u_id` / `SessionId` 正是这类）只存内存、根本不写 SQLite**——
  浏览器一关（更别说强杀）就全丢了。所以主路径是趁浏览器活着直接要。
- **主路径 CDP**（见 `app/cdp.py`，纯标准库：urllib + 手写 WebSocket）：启动 Edge 时带上
  `--remote-debugging-port`，通过 CDP 的 `Storage.getCookies` 从**运行中的浏览器内存**里
  把全部 cookie（含会话态）拿回来，拿完都不用关窗。
- **回退路径 SQLite**（见 `app/edgecookie.py`，纯标准库 `sqlite3` + `ctypes`）：仅当 CDP
  连不上（如窗口已被手动提前关闭且落盘恰好完成）时才读库兜底。
  - 为什么必须用**独立**配置目录：常驻 Edge 会用独占句柄锁住主 Profile 的 Cookies 库，
    复制和直连都会 `PermissionError`；独立目录由本程序起、由本程序关。
  - Cookie 解密：`encrypted_value` = `v10`/`v11` 前缀 + DPAPI 密文，**解密前必须先剥掉 3 字节前缀**，
    再交给 `CryptUnprotectData`。
  - 若 Edge 版本启用了新版「应用绑定加密」（`app_bound_encrypted_value` 列有值），
    纯 DPAPI 解不出来，此时会明确提示降级，不会静默返回空。

失败提示会**原样透出聚水潭服务端给出的原因**（以前统一吞成「账号或密码错误」，真因查不出来）：

- 「账号或密码错误」/「您的账号已禁用…」/「请输入验证码！」… —— 以服务端原话为准，界面上原样显示
- 触发风控滑块 / IDAAS 二次验证 → 提示「该账号触发了安全验证，请先在聚水潭网页端登录一次」
- **其它所有业务接口失败 / 无权限 → 统一弹窗「当前账号无此操作权限」**，不暴露技术细节，程序不崩溃

> 风控参数 `j_d_3` / `v_d_144` 由页面加载的京东 td.js 与阿里云盾 SDK 生成。
> 在本机页面里这两个 SDK 常常取不到值（跨域限制），此时 `v_d_144` 会按官方格式
> `毫秒时间戳_32位十六进制` 本地合成——**实测这一项缺失会直接导致服务端拒登**，务必不要置空。

### 2. 核心收货流程（收货批次模式）

```
创建收货批次 ──► 进入收货状态
                 │
                 ├─ 扫物流单号 ──► 建/切物流单号（子母件、独立单号都行）
                 │                  右侧单号列表逐个折叠展示，扫第二个不会挤掉上一个
                 ├─ 扫商品 69 码 ──► 光标跳到「待确认数量」框（默认 1 且全选）
                 │                    ├─ 直接回车 ──► 本次 +1
                 │                    └─ 改数字再回车 ──► 本次 +该数字
                 ├─ 扫商品编码 / 款式编码 ──► 同上，匹配到同一行累加
                 ├─ 再扫同一物流单号 ──► 回到该单号继续追加，不重复建
                 │
                 ├─「退出批次」──► 挂起（数据全留）──► 可去创建/处理别的采购单
                 │        ▲                                    │
                 │        └──────── 在「挂起中的批次」点一下继续收货
                 │
              ▼
        手动点击「结单」 ──► 合并全部物流单号 ──► 全量差异校验 ──► 单据关闭
```

**采购单号 / 外部单号不用自己选类型**：顶部单号类型默认「**自动识别**」（设置里同样是默认项），
程序会按 采购单号 → 外部单号 → 来源单号 → 线上采购单号 依次试；命中后标题/提示会说明
这次是按哪种号识别出来的（例如「识别为外部单号」）。只有想限定某一种号时才手动选具体类型。

**收货界面分左右两栏**（互相对照，一眼看出还差什么）：

| 位置 | 内容 |
|---|---|
| 左栏「**采购单明细**」 | 这张采购单**该收什么**：每行固定「**商品编码 + 名称**（+ 规格、条码小字）」/ 应收 / 已收，收满打「✓ 已收满」，没收满标「还差 N」 |
| 右栏上部「**物流单号列表**」 | 本批次扫进来的**全部物流单号**，每行折叠显示（新扫的展开、之前的收起），带 `改单号` / `删除` 按钮，点单号即切回去继续补扫 |
| 右栏下部「**当前物流单号明细**」 | 当前这个单号实际收了多少，标题即单号 |

右栏明细排序：**采购单里有的按采购单顺序排在前**，**采购单里没有的（计划外）用一条
「以下为采购单里没有的商品」分隔行隔开、单独沉底**。

关键规则：
- **一张采购单只对应一张收货单**，重复「创建收货批次」会复用并恢复原记录，不会重复建。
- **不再被单一采购单卡住**：收到一半可以点「退出批次」把单据挂起，人立刻空闲，
  去创建或处理别的采购单；挂起的单据在首页「挂起中的批次」里点「继续收货」即可接着扫。
  **同一时刻只有一张处于收货中**，切换时会自动把上一张挂起（避免两张同时亮着）。
- **一个批次里可以扫多个物流单号，互相不覆盖**：每扫一个新单号，它就作为新的一块加到
  右栏单号列表（展开为当前），**之前扫过的单号折叠保留**，不会消失；点该单号（或它的
  「继续补扫」）即可切回去继续往里加商品。数量按「物流单号」分别累计，互不影响。
- **物流单号可整单管理**：
  - `改单号` —— 扫错单号时直接改，明细保持不变（同批次内不允许重名）；
  - `删除` —— 删掉整个物流单号及其全部明细，**弹窗二次确认**后生效，数量同步从采购单实收中扣减。
- 退出/挂起不丢数据：物流单号、商品明细、数量全部保留，恢复后继续累加。
- **扫码录入数量**：扫到商品后**光标停在数量框**、默认值 `1` 且**全选**。
  - 直接回车 → 本次按 `1` 累加；
  - 输入数字再回车 → 本次按该数字累加（是**累加量**不是覆盖值，例如原有 5，输入 10 回车 → 15）；
  - `Esc` 取消本笔，不入账；
  - 还没确认就扫了下一个码 → 上一笔自动按默认 1 入账，光标跳到新码的数量框（连续扫码不停顿）。
- 商品认码顺序（**三级合并 + 款式兜底 + 接口兜底**）：

  | 次序 | 匹配依据 | 界面标注 |
  |---|---|---|
  | 1 | `sku_code` 条码 / 69 码 | （条码命中） |
  | 2 | `sku_auxiliary_code` 辅助条码（逗号分隔） | （辅助码命中） |
  | 3 | `sku_id` 商品编码 | （商品编码命中） |
  | 4 | `i_id` 款式编码（前三项都没命中时兜底） | （款式编码匹配） |
  | 5 | 调**商品资料接口**反查，拿回真实商品编码再回查采购单明细 | （商品资料接口匹配） |

  第 1~3 步**合并判定**：同一个码只要命中**不同商品**就弹窗人工选择——例如 A 的条码
  正好是 B 的辅助码（或商品编码），反之亦然，**绝不按优先级静默取先命中的那个**。
  弹窗里每个候选都给出**商品大图（商品资料接口 `pic` 字段）、商品名、商品编码、条码、
  规格、采购数量、以及它是「条码命中 / 辅助码命中 / 商品编码命中」**，点选后按所选商品直接
  入账（不会再拿原码重扫一次）。同一商品自己条码=辅助码不算冲突，直接唯一命中。
  前四级全在本地完成、零网络；第 5 级只在本地认不出来时才走接口，结果缓存 7 天，
  同一个码不会重复打接口。
- 数量也可在右栏明细表里 `−/＋` 或直接双击输入框手动改。


**数据层级与累加规则**（同一物流单号内同商品累加，不同单号互不影响）：

```
采购单（收货单）            ← 左栏「采购单明细」展示这层的应收/已收
  ├─ 物流单号 A ── 商品X ×N、商品Y ×M    ← 在 A 里再扫 X，N 继续累加
  ├─ 物流单号 B ── 商品X ×K              ← 这里的 X 与 A 里的 X 各自独立
  └─ 物流单号 C ── ...                   ← 右栏单号列表里点哪个，哪个展开为「当前单号」
```

**记录查询（两段式，点进去即展开，无需再点「查看明细」）**：
1. **各物流单号明细** —— 每个物流单号一块独立小表，数量可直接修改、整行可删，单号也可改名或整单删除；
2. **实收汇总与采购单差异** —— 全单实收合计 vs 采购单应收，逐行列出多收/少收。

**历史库自动升级**：旧版用唯一索引 `ux_session_active` 把「同时只能有一张收货中的单」
写死在库里。新版启动时自动删除该索引并补 `paused_at` 列，**不会丢失任何已有记录**，
无需手工处理。`sku_cache` 表也会自动补 `pic`（商品图）列；新增的 `saved_account`
（常用账号）表随建表脚本自动创建。

商品资料反查用到的接口（货主过滤必须写在 URL query 上，写 `data` 里会被静默忽略）：

| 用途 | 接口 |
|---|---|
| 按商品编码取档案 | `POST api.erp321.com/erp/webapi/ItemApi/ItemSku/GetEditOrCreateItemSkuInfoV2?owner_co_id=&authorize_co_id=`（`data` 是**字符串**不是对象，传对象报 10015） |
| 按商品编码/条码检索 | `POST apiweb.erp321.com/webapi/ItemApi/ItemSku/GetPageListV2?owner_co_id=`（注意这个 host 路径**不含** `/erp`） |

只有开启了「设置 → 商品编码反查」才会调用；接口失败或无权限时**自动降级**，不影响继续收货
（此时扫码仍会记为差异行，只是名称显示为「未知商品(码值)」）。实测这一步耗时通常在 200~600ms，
若在 `设置` 里关掉则完全零网络调用。验证这条链路在你账号上是否可用：

```bash
python app/item_probe.py                      # 交互输入账号 / 密码 / 一个条码
python app/item_probe.py 账号 密码 6901234567890
```

脚本会依次打印：登录结果 → 货主与分仓清单 → 三级反查各耗时与命中情况。

### 2.1 选择商家 / 分仓

采购单输入区有 **「商家 / 货主」** 和 **「分仓」** 两个下拉框，数据来自
`ItemApi/PartnerRelation/GetTPWPartnerOwnersV2` 与 `ItemApi/PartnerRelation/GetWmsCoIds`（缓存 12 小时，
可点「刷新清单」重拉）。

- 下拉框显示为 **`中文名称（ID）`** 形式；若接口只给了 ID（没带名称）才退回显示数字
- **分仓接口真实返回是对象数组**，字段名为 `wms_co_id` / `wms_co_name`：
  ```json
  [{"wms_co_id": 15195086, "wms_co_name": "东莞品秀刷货仓", "istpwPartner": true, ...}]
  ```
  曾因名称候选字段漏了 `wms_co_name`（只认 `co_name`/`name`/`short_name`）导致分仓全显示成数字。
  现已把字段候选集中到 `_wms_id()` / `_wms_name()`（货主为 `_owner_id()` / `_owner_name()`），
  兼容 对象数组 / 扁平字典 `{id: 名称}` / 二维数组 `[[id, 名称]]` 三种形态
- 货主接口 `GetTPWPartnerOwnersV2` 返回 `[{"consignor_co_id":..., "consignor_co_name":...}]`（也兼容字典）
- **缓存带版本号**：清单缓存 12 小时，写入时带 `ver`；若读到的缓存 `ver` 与
  `server.PARTNERS_CACHE_VER` 不符，或存在「名称 == ID」的坏数据，一律视为失效自动重取——
  避免"代码已修好、旧坏缓存还在供数据"这种情况
- 默认 **自动识别**：按上次成功的上下文 → 设置里的额外货主 → 通用兜底 依次轮换尝试
- 其他分仓的单据：手动指定后，查询时会**优先**用这组货主/分仓；仍查不到会自动回落轮换
- 选择结果记住在设置里，下次启动保持
- 排查用只读端点 **`GET /api/debug/wms-raw`**：原样吐出分仓/货主接口的原始返回与解析结果，
  不写缓存；另可在 `data/diag.log` 查看解析失败时的取证日志

顶部常驻状态条：**当前采购单号 · 已录入子批次数量 · 已扫商品行 · 总实收进度条 · 【结束采购单收货】红色按钮**。

扫码枪适配：主输入框始终自动聚焦（点空白处、切 Tab、扫完一笔都会回来），扫码枪自带的回车即提交，全程无需点击鼠标。快捷键 **F1 = 物流单号模式，F2 = 商品条码模式**。

### 3. 差异校验

手动点「结束采购单收货」时自动全量比对，并弹窗展示结果（红底标出）：

- 以采购单原始明细为基准（数量取 `qty`），汇总**所有子批次**的实收数量
- 实收 ≠ 采购数量 → 该行标红，标注 **少收 N / 多收 N**
- 实收商品不在采购单明细内 → 整行标红，标注 **采购单无此商品**

### 4. 记录查询

两个输入框都支持**模糊匹配**（输入片段即可），搜索范围：

| 查询维度 | 可模糊匹配的字段 | 展示内容 |
|---|---|---|
| 按采购单号 | 采购单号 / 外部单号 / 输入单号 / **供应商名称** | 全部收货子批次、总实收明细、差异记录、收货起止时间 |
| 按物流单号 | 物流单号 | 定位到子批次，展示所属采购单号、首次扫描时间、该批次商品明细 |

### 4.1 记录的修改与删除

历史记录同样可以直接改，**不区分单据是否已结束**：

| 操作 | 位置 |
|---|---|
| 改数量 | 查询结果里的数量输入框，直接改数字后回车/失焦即生效 |
| 删除单行商品 | 该行最右侧 `✕` |
| 改物流单号 | 每个物流单号标题旁的 `✎`（收货页的单号列表里也有「改单号」） |
| 删除整个物流单号（含其明细） | 采购单查询结果里每个单号后的 `✕`、物流单查询结果底部的「删除该物流单」、收货页单号列表里的「删除」 |
| 删除整张采购单记录 | 采购单结果底部的「删除整单收货记录」、「最近收货记录」里的「删除记录」 |
| 导出该单明细 | 采购单结果底部的「导出该单明细」 |

删除类操作都会弹二次确认。删除后对应数量实时从「总实收进度」和差异表里扣减；
在「挂起中的批次」里删除后，该条目当场消失（不必再手动刷新页面）。

### 5. 导出

支持 **CSV / Excel(.xlsx)**，可按**单采购单 / 物流单号 / 时间范围 / 全部**导出。
列顺序严格固定为 6 列：

| 采购单号 | 对应物流单号 | 扫描时间 | 商品编码 | 商品名称 | 数量 |
|---|---|---|---|---|---|

其中「扫描时间」= 该物流单号子批次的**首次扫描时间**。导出文件落在程序目录下的 `导出/` 文件夹。

## 四、用到的聚水潭接口

| 用途 | 接口 |
|---|---|
| 账号密码登录 | `POST api.erp321.com/erp/webapi/UserApi/WebLogin/Passport` |
| 图形验证码 | `GET www.erp321.com/ValidCode.aspx?channel=login&id=<账号>&t=<毫秒时间戳>` |
| 短信验证码下发 | `POST api.erp321.com/usercenter/AuthApi/WebLogin/SendVerificationV2` |
| 短信验证码登录 | `POST api.erp321.com/usercenter/AuthApi/WebLogin/VerificationV2` |
| 采购单列表 | `POST www.erp321.com/app/scm/purchase/purchasemode.aspx` → `LoadDataToJSON` 回调 |
| 采购单明细 | `GET www.erp321.com/app/scm/purchase/purchaseitem.aspx?po_id=...` → 页内 `#_jt_data` |
| 商品档案（编码） | `POST api.erp321.com/erp/webapi/ItemApi/ItemSku/GetEditOrCreateItemSkuInfoV2` |
| 商品检索（编码/条码） | `POST apiweb.erp321.com/webapi/ItemApi/ItemSku/GetPageListV2` |
| 货主清单 | `POST api.erp321.com/erp/webapi/ItemApi/PartnerRelation/GetTPWPartnerOwnersV2` |
| 分仓清单 | `POST api.erp321.com/erp/webapi/ItemApi/PartnerRelation/GetWmsCoIds`（`data` 为字符串 `AddAllWms`） |

登录、采购查询和扫码收货仍以查询/本地落库为主。新增「按实收生成入库单」会在用户预览并确认后写入聚水潭待入库草稿；不调用确认入库接口。详见下方及 `更新说明-实收入库.md`。

### 接口要点（抓包踩过的坑，代码里已处理）

- 列表筛选是数组语法 `[{k,v,c}]`，`c` 取 `@=`（包含）或 `=`（等于）；单号字段 key 恒为 `po_id`，
  具体查哪种号由 `poid_type` 决定（`po_id`/`outer_po_id`/`source_o_id`/`plat_so_id`）
- `status` 传空串会返回 0 行，所以干脆不带这一项
- `__VIEWSTATE` 有时效，每次调用前从列表页重新取（代码内做了 60 秒缓存）
- 读方法（`LoadDataToJSON`）不能带 `CallControl`，带了报 `120009`
- 明细数据不在 AJAX 里，是服务端渲染进 `#_jt_data`，需要抠 HTML
- **分仓清单返回对象数组**，字段是 `wms_co_id` / `wms_co_name`（不是 `co_id`/`co_name`）；
  只认 ID 不认名称会把中文仓名显示成数字。名称候选见 `jst.py::_WMS_NAME_KEYS`
- **清单缓存有版本号** `server.PARTNERS_CACHE_VER`，字段候选变更时把它 +1，
  旧缓存即自动失效重取；同时「名称 == ID」的坏缓存也会被拒

## 五、常见问题

**Q：登录不上去怎么办？**

先重开工具试一次——现在的界面会**直接显示聚水潭服务端给的原因**，照着处理就行：

| 界面提示 | 处理办法 |
|---|---|
| 账号或密码错误 | 注意大小写，或先在网页端登录一次确认密码 |
| 您的账号已禁用… | 让公司管理员在聚水潭「用户及权限」里启用该账号 |
| 请输入验证码！ | 先去聚水潭网页端正常登录一次（可能触发过验证码），再回来 |
| 该账号触发了安全验证 | 同上，网页端登录一次解除风控 |
| 网络异常 / 请求超时 | 多半是本机代理拦了 HTTPS，见下 |

**Q：要输入图形验证码了，在哪输？**

A：服务端要求时会**自动**在登录页展开「验证码」一栏并加载图片，点图片可换一张。
不想打验证码的话，换「短信验证码」标签用手机号登录即可。

**Q：短信验证码收不到 / 提示「账号已禁用，请咨询在线客服（多半是该手机号没有绑定聚水潭账号）」？**

A：先确认这个手机号就是聚水潭账号**绑定的手机号**（可以在网页端「个人设置」里看）。
服务端对「号码没绑账号」「号码不合法」都返回同一句伪装文案（码 `301046`），不要被原话误导。
另一种情况：手机号绑定了多个账号，界面会要求补「手机号后两位」，补完再点获取。

**Q：扫码后没自动进入系统 / 强制取回时提示读不到 Cookie？**

A：按顺序排查：

1. 是否真的在弹出的窗口里**登录成功并进入了聚水潭主页**（只扫了码没点确认不算）——
   正常情况下进入主页后 2 秒内本工具会自动检测到并直接进系统，无需点任何按钮；
2. 若没自动进：看服务端日志里 `qr window opened kind=... cdp=...` 一行，
   `cdp=ready` 说明调试端口正常（主路径可用）；若不是 `ready`，多半是端口被占，
   删掉 `data/edge-login` 目录后重试（会重建干净配置并重挑端口）；
3. 手动兜底按钮走「CDP 优先 → 关窗后读库」两条路：窗口还活着时走 CDP 从内存取，
   已被手动关掉时才读 Cookies 库——此时若提示「应用绑定加密」，
   说明本机 Edge 版本较新、Cookie 被系统级加密保护，改用密码或短信登录；
4. 只扫了码但没在手机上点「确认登录」，会话里不会出现 `u_id`，等多久都不会进。

还是查不出就来跑自助诊断，它会打印服务端的**原始响应**：

```bash
python app/diag.py                    # 交互输入账号密码（不回显）
python app/diag.py 13800138000        # 只带账号
```

诊断会依次检查：代理环境 → 域名解析 → 系统代理/直连两条路的连通性 → 真实登录请求与完整响应体。
密码只在内存里用，不落盘、不打日志。

**Q：本机有网络代理会不会影响？**
A：可能。程序默认走系统代理；公司代理若拦截 HTTPS 会登录失败。
可用 `set no_proxy=erp321.com` 后再双击启动脚本，让它直连。

**Q：提示「当前账号无此操作权限」但账号确实是管理员？**
A：这个弹窗覆盖了「真没权限」和「接口调用失败」两类情况。最常见原因是**货主上下文不对**——
采购单列表必须指定正确的 `owner_co_id`。到「设置」里把该采购单所属货主的 ID 填进「额外货主 ID」
（多个用逗号分隔），重新激活即可。

**Q：怎么拿到货主 ID？**
A：现在不用自己找了——收货页下拉框会列出账号可代销的全部货主与分仓。
只有在下拉框里也找不到该货主时，才把 ID 填进「设置 → 额外货主 ID」（多个用逗号分隔）。

**Q：第一次发货(=无明显物流单)怎么收货？**
A：点「跳过物流单直接收货」，会自动建一个 `NOSHIP-时间戳` 的占位子批次。

**Q：收货记录存在哪？换电脑会没吗？**
A：存在本机 `data/jst.db`（SQLite）。换机器请复制这个目录；也可用「导出」把明细导出成表格。

**Q：关闭窗口后进程还在吗？**
A：未启用PDA时，窗口心跳停止后服务自动退出；启用PDA期间电脑服务会继续运行，需在「设置 → 停用并撤销全部设备」后再退出。

## 六、安全提示

- 登录密码按聚水潭现有机制**明文 POST**，请只在可信内网使用。
- 程序不保存密码，只把登录态 cookie 放在内存里；关掉进程即失效。
- `data/jst.db` 里是收货业务数据，`导出/` 是导出结果，都不含凭据。

### 使用

1. 在收货页面点 **按实收生成入库单**；也可在「记录查询」的采购单记录/最近记录里打开。
2. 核对原货主和仓库公司，选择具体入库仓库；再核对本次物流单号、商品及实收数量，然后点 **确认按以上实收生成待入库单**。
3. 完成后记录显示聚水潭入库单号。到聚水潭检查仓库、成本等信息后，再自行确认入库。

一次操作汇总当前收货批次中**尚未关联入库单且存在正数实收**的物流子批次；
同 SKU 实收累加，排除零数量、不使用采购数量或采购未入库数量。
已生成的物流子批次会锁定，不能继续改量/删除/改单号。
后续补收请新建物流子批次；下次只生成新增子批次，不会重复包含以前的数量。
挂起和已结单记录也能生成。设置中的「校验采购单明细」默认开启：未匹配采购单、最新采购单中缺失或重复的商品会在写入前拒绝。
关闭后不再要求实收商品匹配采购单，按「添加商品」接口加入草稿，再覆写为实收绝对数量，不修改采购单；采购单外商品请核对商品编码和ERP成本价。
无论开关状态如何，非法数量、错误货主/仓库、重复请求、远端回读数量不一致仍会阻止完成；该开关不是关闭ERP自身的权限或业务校验。
设置保存在确认快照中；修改设置后需重新预览，已有入库记录续作使用原设置。详见《更新说明-入库明细开关2.0.1.md》。

### 异常与重试

- 已取得入库单号但添加商品/改量中断：点 **继续完成原单（不重建）**，按原快照覆写绝对数量，再回读校验。
- 新建请求网络中断、不能判断服务端是否已建单：保持锁定，**禁止自动重建**。先到聚水潭按采购单核查，
  填入原单号再「关联原单并核对」。为避免覆写别的入库单，只接受同采购单的空草稿或实收数量完全一致的原单。
  若核查仍无法找到原单，请联系维护人员核查记录，勿删库或直接再开一张。
- 新建接口明确返回业务拒绝（例如无权限）：保留失败记录，但不锁实收，修正原因后可以重新预览。
- 完成记录只是“草稿数量已回读核对”，**不代表已经正式入库**。
- 若上游创建接口保留未实收商品的零数量行，程序保持其为零，不会补入应收数量；正式入库前请在聚水潭检查/清理零数量行。

### 新增接口与数据

| 本地接口 | 用途 |
|---|---|
| `GET /api/inbound/preview?sid=<收货批次ID>&wh_id=<仓库ID>` | 获取未生成实收快照、校验指纹和历史记录（不写 ERP） |
| `POST /api/inbound/create` | `{sid, wh_id, fingerprint, confirmed:true}`，按刚确认的快照生成 |
| `POST /api/inbound/resume` | `{job_id, confirmed:true[, io_id]}`，继续/关联原单 |

`inbound_job` 保存公司上下文、确认快照、远端单号、状态和错误；`inbound_batch` 绑定本地物流子批次。
SQLite 新增表和保护触发器，旧库自动迁移，不删改既有收货数据。升级前仍应先关闭旧程序并备份整个 `data` 目录。

远端只调用项目自带接口文档已记录的方法：`NewWithPurchaseByPoIds(po_id,false)`、`AddItems`、`UpQtyBatch`，
开启校验时读取最新采购单明细；两种模式都读取入库明细回读核对。写回调带 `CallControl:"{page}"`，读回调不带。
**不调用 `ConfirmBatch`，不做自动审核、推送或正式库存入账。**

离线测试：`python app/regression_runner.py`（当前共11套，含PDA权限/备份/幂等及既有业务回归）。
本版本已做模拟接口回归和本地浏览器验收，**未使用真实聚水潭账号做在线开单测试**；
首次使用请先选一小批实收，在聚水潭核对草稿的商品、数量、仓库和价格，再正式确认。
