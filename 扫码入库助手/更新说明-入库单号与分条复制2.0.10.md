# 扫码入库助手 2.0.10：入库单号与微信分条复制

## 这次按要求调整
1. **有入库单号时，同步放进复制文字和结果图片顶部。** 多张单号一起列出并去重；没记录单号时不造号、不显示空的入库单行。
2. **去掉报告底部的固定说明**：“本轮应收按开始时的ERP余量固定；本报告不是ERP入库确认凭证。”文字和图片都已去掉。计算口径并未变化。
3. 增加“微信分两条发送”区域：先只复制文字，再只复制图片，避免依赖微信对混合格式剪贴板的选择。

## 怎样发成一条文字消息 + 一条图片消息
1. 点击 **① 复制单号文字**。此时剪贴板只有文字，包含采购单、外部单号和已有入库单号。
2. 切到微信，粘贴并发送，得到第一条文字消息。
3. 回到助手，在“图片范围”选 **仅差异（含待核实）** 或 **完整（含已收满）**，点击 **② 复制图片**。
4. 回到微信，粘贴并发送第二条图片消息。

**请先发送文字，再复制图片。** 第二次复制会替换剪贴板内容。程序不会切换微信、挑选联系人或自动按发送。

### 为什么不是一次复制、一次粘贴自动发两条
剪贴板是内容交换机制，不是微信发送队列。可以同时写入文字/PNG/HTML供应用选择，但不能要求微信把一次粘贴自动拆成两条独立消息。

原来的 **“复制完整结果（含已收满）”和“仅复制差异”** 仍保留图文组合格式。不同微信/办公软件版本可能只采用其中一种；如果希望明确分成两条，请按上面的两步复制流程。

## 入库单号来源与范围
- 读取本软件中**当前这一轮收货**已记录的入库单号，包括已生成但尚未完成后续核对的原单。
- 只列有实际单号的记录；创建被拒绝的记录不列。不同收货轮次、其他公司、其他采购单的入库单号不混入。
- 不因显示单号而声称已确认入库；也不主动去真实ERP新建、确认、取消或补绑入库单。
- 如果只在ERP外部操作过、尚未被本软件记录或关联的单号，本版不会自动发现。
- 结单结果、历史“查看明细与差异”和按采购单查询中的核对报告使用同一份单号信息。

## 2.0.9功能保留
- 结单和历史默认仅显示差异；待核实、未扫码、少收、多收保留，已收满可切回全部查看。
- 完整复制包括已收满商品；仅差异复制只包括差异及待核实，不受屏幕显示勾选影响。
- 图片从完整数据生成，不只截当前滚动可见范围。单图超过30000像素高度时明确失败，不悄悄截断。
- 商品信息仍包含编码、商品名、69码/条码或辅助码、采购/ERP入库、本轮应收/已收及差额。
- 图片复制失败会提供保存PNG和预览；单号文字复制失败会提供可手动选中的文字框，不假报成功。

## 数量逻辑不变
仍按2.0.8确认的逻辑：本轮应收按本轮开始时的采购数减ERP入库数固定；本轮已收是本轮全部物流单的本地收货合计。ERP刷新不会重算本轮目标。显示入库单号或删除说明文字都不改变数量。

## 升级
关闭原电脑端，把“电脑端/扫码入库助手.exe”替换到原目录，保留原data和导出文件夹，再启动。版本为 **2.0.10-inbound-report**，按已有机制进行升级前备份。

**PDA仍是2.0.8，无需重装。** 包内APK及内置下载APK与原208逐字节一致，签名未改变。旧版ZIP不覆盖。

使用临时数据库、模拟ERP和独立无头Edge验证；真实读回本机剪贴板，分别确认纯文本模式只有text/plain、图片模式只有image/png，组合模式有PNG/文字/HTML。已校验Canvas实际绘制的入库单号、删除页脚、多单号、无单号及范围隔离。
