# 2.0.4 收货资料编辑与入库修复

## 本次变化
- 修复入库回调参数类型造成的“对象必须实现 IConvertible。”：换仓 Save、采购明细检查 CheckAndChoose、按明细添加 AddItemsUnify 按官方协议发送 JSON 字符串，不再把对象/数组直接作为参数。
- 商品资料搜不到也能在收货批次确认数量，作为非采购单商品保留。确认后点“编辑资料”，可改当前物流子批次这一行的商品编码、名称、条码、规格；数量保持不变。电脑收货页/记录明细与 PDA 均支持。
- 手改编码后重新按原采购明细精确匹配；匹配到采购单商品会转为采购商品行。不修改远端采购单、不自动创建远端商品资料。
- 同一物流子批次已有目标编码时提示核对，不自动合并两行；其他终端修改了数量或资料时要求刷新。已关联入库单的明细仍锁定。
- 生成入库前，按收货批次保存的货主与仓库公司，实时精确查询所有商品编码。商品资料不存在时列出编码并停止，检查在创建远端草稿之前进行；查询失败也停止，不跳过验证。继续原单同样核验。
- 设置中的“校验采购单明细”保留。关闭时，采购单外但商品资料存在的商品通过“添加商品”加入入库单；不能用此开关跳过商品资料存在性检查。
- 扫码仍优先采购明细/本地商品库，每6小时自动同步的逻辑不变。强制商品资料查询仅在生成/续填入库时执行，不给每次扫描新增实时请求。

## 升级
1. 先在旧版设置备份；停用 PDA，退出旧主机服务。保留旧 EXE 同目录的整个 data 文件夹，不要删除数据库或登录资料。
2. 用包内“电脑端/扫码入库助手.exe”替换原 EXE，保持原 data 位置；不要同时启动新旧版操作同一数据库。新版首次启动会做升级前备份。
3. PDA 安装包升级为“扫码入库PDA-2.0.4.apk”，与原版签名相同，可覆盖安装；重新配对。新编辑功能需要电脑端也升级到2.0.4。仍要求 Android 8.0+。
4. 如果只是收货记录中名称/编码不对，直接编辑该行；不需要重新扫描累加数量。编辑后需重新打开入库预览再确认。
5. 旧版已经创建的空单不要再建。原入库记录点“继续完成原单”；若显示结果不明，先核实原单号后关联。已有入库记录的校验开关沿用原确认快照，不由后来设置偷偷改变。

## 边界
- 本功能只生成/续填“待入库”草稿，不执行正式确认入库；正式入库、成本及差异由仓库人员核对。
- 手工填写名称不代表聚水潭已有该商品，最终以当前货主下的商品编码查询为准。
- PDA 为局域网伴随客户端，电脑保持运行。未确认请求先核实，不能靠重新扫码重试。
- 本版通过本地模拟浏览器、回归和签名/资源一致性检查；没有在实体 PDA 上测试扫描枪型号与系统兼容性。
