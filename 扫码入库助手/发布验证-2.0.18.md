# 2.0.18 发布验证

版本标识：`2.0.18-stable-inbound`。基线为已交付的 2.0.17。

## 变更与隔离
- 正式代码：`app/server.py`、`service_runtime.py`（新增）、`store.py`、`inbound.py`、`backup.py`。
- 页面：`web/inbound.js`、`app.js`、`index.html`、`style.css`；`purchase-watch.html` 与 `unplanned.html` 只增加网页图标引用。
- 图标：应用根 `app.ico`，以及 `web/app-icon.svg/png`。现有 build_exe.spec 自动使用 app.ico，无需修改构建结构。
- 新测试：`inbound_modes_test.py`（19项）、`inbound_modes_http_test.py`（7项），独立 fixture、浏览器脚本、EXE 生命周期/资源/字节码验证脚本。
- 旧测试的两处错误文案断言和收货轮次 fixture 快照同步到新格式；业务断言未删减。
- 修改前备份：`_backup/stability218-20261004-175434`。
- 不接触生产 data / 商品库 / 凭据，不运行 po1323929_repair.py，不操作真实 ERP 库存，不使用无关浏览器或 Android 签名。

## 结果
- 原 regression_runner：12 套全部通过。
- 新入库模式单元 19 项 + HTTP 7 项：通过。覆盖排除清单、先单内后单外、模式/仓库指纹、同/不同模式并发、空单阻止、商品不存在、最新采购变更、未知结果/续原单、SQLite 锁、重启和旧库迁移。
- 采购工作台删除及原功能 38 项、扫码过滤 21 项、无采购单 16 项、暂存 HTTP 10 项：通过。
- 新真实页面浏览器 12 组：通过；包含两选项、切换重算、仓库确认、防重复/关闭、部分生成后补单外、模拟 ERP 两张待入库草稿、每次重选、移除设置、桌面/窄屏/登录截图。
- 旧暂存页面 15 组、采购导航页面 17 组：通过；差异灰/黄/绿语义不变。浏览器测试阻止外部请求。
- 全 web JS 语法检查通过。
- 最终 EXE 实际内嵌 server 与 15 个模块字节码对比源码；禁网络执行 139 项测试通过，包含新增入库模式。真实 PE 图标资源至少 7 个尺寸，SVG/PNG/页面资源逐字节匹配。
- 实际 EXE 临时库完整 HTTP 冒烟通过：收货轮次、余量、扫码禁用过滤、设置兼容、PDA权限与APK字节、版本备份、暂存及差异入口等。
- `exe_lifecycle218.py`：未设置 JST_NO_WATCHDOG；启动后 40 秒无心跳仍运行；收到一次心跳后 125 秒无任何 HTTP 请求仍存活且可恢复访问；失联/恢复日志、本版同目录重复启动复用、结束进程树后更换服务 PID 重启并保留临时数据均通过。仅设置 JST_NO_BROWSER 防止测试弹窗。
- 生命周期测试的早期清理/PID读取脚本问题已修正：必须终止 PyInstaller 整个测试进程树；读取实例元数据应跳过被 OS 锁定的首字节。未通过的早期结果不作为交付证据。

## 构建与交付校验
在应用目录执行：
```
../.build-env/Scripts/pyinstaller.exe build_exe.spec --noconfirm --distpath ../release-stability218-dist --workpath ../release-stability218-build
```
最终 EXE SHA256：`a28dc93e3902db8eafb34171d003d174ab5d3b034cb431c5fa76081299276099`。
ZIP 使用显式白名单；不包含生产数据、浏览器配置、账号材料、证书私钥、签名材料或日志。每个文件在 manifest-sha256.json 有大小与哈希；另执行 ZIP 完整性及逐文件 SHA256 校验。PDA 固定为 2.0.8。

- 建单写入只在 FakeJst 协议模拟中验证。真实账号权限、采购日期/完成状态及 ERP 成本继承未实号写验证。
- 只生成待入库草稿，不自动确认库存；不写价格、成本、供应商。历史未明结果仍需关联原单，禁止猜测重建。
