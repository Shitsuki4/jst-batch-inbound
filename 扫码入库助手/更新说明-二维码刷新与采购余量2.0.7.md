# 扫码入库助手 2.0.7：二维码刷新与采购剩余应收

## 本次变化
- 微信/钉钉二维码刷新优先复用当前官方登录窗口，减少反复冷启动；官方页面尚未准备好时适度重试。失效则重新打开专用窗口，不绕过绑定或安全校验。
- 每次主动查询、查看详情、恢复收货或手动刷新采购状态，都按原采购单及原货主/仓储公司重新获取ERP状态和明细。
- 剩余应收 = 采购明细数量 − ERP已入库数量，最低为0。例：采购12、已入2，显示剩余10。
- 本地累计、待生成和已关联数量独立显示，不从ERP余量重复扣减；已关联入库草稿不代表ERP已入库。
- 缺失/无效/旧版未验证的计数显示待核实，不能默认为已入0。
- 重复SKU合并展示，不重复累加本地收货；显示最后成功获取时间，刷新失败不会伪装成最新成功。PDA切单失败不残留上一单明细。
- 两秒自动同步仍只读取电脑本地数据，不每两秒请求ERP。

## 升级
1. 结束当前操作并退出旧电脑端；备份原data目录，不删除数据库或旧版本文件。
2. 将新版EXE放到原程序所在目录、与原data同级再运行，避免在新空目录中误以为历史丢失。程序升级前自动进行数据库备份。
3. PDA安装随包2.0.7 APK（versionCode=20007），沿用原签名，不卸载旧版以免清空设备配置；电脑端内置扫码下载也为2.0.7。
4. 查询一张已部分入库的采购单，核对采购量、ERP已入库量、剩余应收和最后成功时间。

## 验证与边界
- 已用用户指定的真实部分入库样例只读核对：采购12、ERP已入2、差异10，关联已入库单数量2。没有新建、修改或确认ERP业务单据。
- 本次真实查询范围没有有效待入库草稿，因此不将有效草稿计数语义宣称为实测通过。已关联数量独立展示的规则由离线回归覆盖。
- 结单差异表仍对照“采购总计划 vs 累计本地实收”，不是“本次收货 vs ERP剩余”。
- 二维码曾在官方页面只读刷新测试通过，实际速度受网络与官方服务影响。此前短信登录已真实成功，不需要重复短信验证码测试；历史故障唯一根因未被确认。
- Android6兼容编译/签名/资源检查不等于真机和扫码枪验收，实体设备操作仍需现场确认。
- 不包含业务数据库、登录凭据、浏览器profile、HAR、现场取证文件或签名私钥。测试浏览器继续保持打开，无后台自动抓包。

## 本次构建验收
- 采购余额与显式刷新离线回归15项通过。
- 桌面界面及APK转译后的PDA脚本通过SKU合并、刷新失败跨后台轮询、时间戳、采购改量、未知值、切单失败与恢复用例；使用模拟ERP响应，不冒充真机实测。

- 独立临时数据库启动EXE，HTTP余额、内置安装包、升级备份与未登录操作拦截测试通过；无真实ERP写入。
- APK为2.0.7/20007，最低Android6，原签名v1/v2/v3验证及ES5资源校验通过。
- 旧版2.0.6 ZIP和APK的SHA256未变化。
